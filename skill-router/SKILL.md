# /skill-router — เลือกสกิลให้อัตโนมัติจากประโยคสนทนา

ผู้ใช้มักพิมพ์งานแบบธรรมชาติ ("ช่วยเขียน...", "ทำ...ให้หน่อย", "อยากได้...", "สรุป...") โดยไม่รู้ว่าควรใช้สกิลไหนในคลัง 217+ ตัว สกิลนี้ทำหน้าที่ "ตัวกลาง" จับใจความแล้วเลือกสกิลที่ตรงที่สุดมาทำงานให้

## ใช้ตอนไหน
- ผู้ใช้ขอความช่วยเหลือด้วยประโยคทั่วไป ที่ยังไม่ได้พิมพ์ `/<ชื่อสกิล>` ตรงๆ
- ผู้ใช้ถามว่า "เรื่องนี้ใช้สกิลไหนดี" / "มีสกิลช่วยเรื่อง... ไหม"

## ขั้นตอน
1. **อ่านประโยคผู้ใช้** จับโครง: การกระทำ (verb เช่น เขียน/ร่าง/สรุป/วิเคราะห์/วางแผน/คุยกับ) + เป้าหมาย (object) + บริบท (เพื่อใคร/แพลตฟอร์ม/สถานการณ์)
2. **เปิดคลังสกิล** `skill-catalog.md` ที่รากของ bundle — มีทุกสกิลพร้อมคำอธิบายและกลุ่ม
3. **ให้คะแนนความตรง** ของแต่ละสกิลจากคำสำคัญ + ลักษณะงาน เลือก top 1-3
4. **ตัดสินใจ**:
   - ถ้ามีตัวเด่นชัดเจน 1 ตัว → บอกผู้ใช้ว่าจะใช้สกิลไหน (พร้อมเหตุผลสั้น) แล้ว **ลงมือทำตามสกิลนั้นทันที**
   - ถ้ากำกวม (หลายตัวใกล้กัน) → เสนอ 2-3 ตัวเลือกสั้นๆ ให้ผู้ใช้เลือกก่อนทำ
   - ถ้าไม่มีสกิลตรงเลย → บอกตรงๆ ว่าไม่มี แล้วทำงานนั้นแบบทั่วไป + เสนอสร้างสกิลใหม่ (ดู `skill-creator` ถ้ามี)

## รูปแบบการตอบ
```
เข้าใจว่าต้องการ: <สรุปงานหนึ่งบรรทัด>
ใช้สกิล: /<slug> — <เหตุผลสั้น>
(ทางเลือกอื่น: /<slug2>, /<slug3>)
```
จากนั้นลงมือทำตามขั้นตอนของสกิลที่เลือก โดยถามข้อมูลที่สกิลนั้นต้องการก่อน

## เคล็ดลับ
- คำว่า "สรุป" กำกวม: สรุปประชุม / สรุปเปเปอร์ / สรุปภาษี / สรุปเคส — ดูบริบทหรือถามให้ชัด
- คำว่า "เขียน/ร่าง" + เอกสารธุรกิจ → ชุด B/A; + โค้ด/เทคนิค → ไม่อยู่ในคลังนี้ ทำแบบทั่วไป
- งาน "คุย/รับมือ/ทำงานกับคน [type หรือ ราศี]" → ชุด E (people-skills)
- งานหางาน/อาชีพ → ชุด C (career-job)
- ต้องการแค่คุมรูปแบบคำตอบ (สั้น/ขั้นตอน/checklist) → ชุด C (output-modes)

## ข้อควรระวัง
- เลือกจาก `skill-catalog.md` เท่านั้น — **ห้ามแต่งชื่อสกิลที่ไม่มีอยู่จริง**
- ถ้าไม่มั่นใจ อย่าเดาแล้วลุยเลย ให้ยืนยันตัวเลือกกับผู้ใช้ก่อน
- งานบางอย่างใช้หลายสกิลต่อกันได้ (เช่น วางแผน → เขียนคอนเทนต์) เสนอเป็นลำดับได้
