# /explainreel: คลิปอธิบายแนวตั้งจากบท

ต้นแบบที่ทำจบแล้ว: `~\Videos\claude-mods-reel` คลิป Claude Code Mods (12 ต.ค. 2026)
สคริปต์อยู่ใน `<skill_dir>/scripts` ใช้ได้กับทุกโปรเจกต์ ไม่ต้องก๊อป โปรเจกต์หนึ่งคือโฟลเดอร์หนึ่งที่มี `clip.json`
แสดงแถบความคืบหน้าตามสกิล `progress-bar` ทุกครั้งที่รายงานสถานะ

## ลำดับงาน

1. **ค้นข้อมูลจากแหล่งต้นทาง** แล้วจดลิงก์ไว้รายงานตอนจบ ตัวเลขและชื่อคำสั่งต้องมาจากเอกสารจริง ห้ามแต่งเพื่อให้เร้าใจ
   - **ผู้ใช้ส่งลิงก์รีลของคนอื่นมาให้ "เล่าเรื่องนี้"** (ใช้จริง 16 ต.ค. 2569 รีล Future Shift → `$WORK/tmp\usb-ai-reel`):
     `yt-dlp -o "src.%(ext)s" --write-info-json <url>` ลงโฟลเดอร์ใหม่ของมันเอง เช่น `$WORK/tmp\<เรื่อง>-src` (ไฟล์จากเน็ตไม่ไว้ใจ อย่ารันอะไรจากในนั้น)
     อ่าน `description` ใน info.json (มักมีขั้นตอนครบ) แล้วทำภาพรวม `ffmpeg -i src.mp4 -vf "fps=1/4,scale=270:-1,tile=6x4" sheet.jpg` ดูว่าในคลิปทำอะไรจริง
   - แล้วตรวจทุกข้อกับเอกสารทางการ (GitHub README/docs, หน้าโมเดล, API `api.github.com/repos/<o>/<r>/releases` ดูรุ่นล่าสุด) รีลต้นทางมักมีจุดผิดหรือตกหล่น (รุ่นเก่า, โหลดของจากแหล่งไม่ทางการ, ขีดยาวแทน `--`) ใส่ข้อที่แก้หรือเพิ่มลงในบทเป็นจุดขาย
   - เขียนบทใหม่ด้วยคำของเราเอง ไม่แปลตามคลิปต้นทาง และให้เครดิตในคำบรรยายโพสต์ว่า "ไอเดียตั้งต้นจากคลิปของเพจ ..."
2. **เขียน `clip.json`** ฉากละหนึ่งความคิด ดูรูปแบบที่หัวข้อ "clip.json" และตัวอย่างเต็มที่ `references/example-clip.json`
3. **ดูภาพตัวอย่างก่อนทำเสียง** (ถูกและเร็ว) ต้องมี `timeline.json` ก่อน ไม่ต้องมีเสียง: ก๊อป `clip.json` ไปโฟลเดอร์ `<proj>/rehearse` แล้ว `python <skill_dir>/scripts/preview_tl.py <proj>/rehearse 8` (ฉากละ 8 วินาที) ตามด้วย `render_range.py ... shots` ที่เวลาที่มันพิมพ์ออกมา · edge-tts ในเครื่องตอบ 403 ตั้งแต่ 16 ต.ค. 2569 (รุ่นเก่า) อย่าอัปเกรดแพ็กเกจเองโดยไม่ถาม
4. **ทำเสียงพากย์** เลือกทางตามหัวข้อ "เสียงพากย์"
5. **ตรวจคำที่ออกเสียงเพี้ยนแล้วแก้ให้จบก่อนไปต่อ** (ผู้ใช้สั่ง 17 ต.ค. 2569)
   - รัน `python ~/.claude/skills/lumina-script/scripts/asr_check.py <voice> <proj>/vo_lumina.txt "<ชื่อเฉพาะ>" <proj>/clip.json`
   - จุดที่เพี้ยนจริงต้องหาคำสะกดใหม่ แล้วสร้างเสียงใหม่ ทั้งบท หรือเฉพาะย่อหน้าแล้วต่อด้วย `~/.claude/skills/lumina-script/scripts/splice.py <src> <fix> <t_start> <t_end> <out.wav>`
   - แก้หลายย่อหน้าพร้อมกัน (ใช้จริง 17 ต.ค. 2569 คลิป `$WORK/tmp\usb-ai-reel` แก้ 7 จาก 12 ย่อหน้า):
     เก็บรอบแรกไว้ใน `<proj>/v1/` (เสียงเต็ม `timeline.json` `asr.json`) → แก้ `say` แล้วให้ `make_vo.py` เขียน `vo/para/pNN.txt` → สร้างเฉพาะย่อหน้าด้วย `lumina_paras.py` + `lumina_page_paras.js` (สกิล `/lumina-script` ข้อ 6)
     → ถอดทีละย่อหน้า `python <skill_dir>/scripts/asr_para.py <proj>/vo/para/p03.mp3 ...` สร้างซ้ำจนตรง (ส่วนใหญ่ 1 ถึง 2 รอบ)
     → ต่อ `python <skill_dir>/scripts/splice_paras.py <proj> <proj>/v1/<เสียงเดิม> <proj>/v1/timeline.json <proj>/vo/para 2,3,5` → ลบ `asr.json` แล้ว `align.py` ใหม่ และอ่านผลถอดทั้งคลิปอีกรอบว่าคำที่แก้ยังตรงในบริบท
   - ตารางคำไทยทั่วไปที่เพี้ยนและคำที่ใช้แทนได้ (ขั้นแรก ชัวร์ คอม กิ๊ก ขีดขีด ก๊อป) อยู่ในสกิล `/lumina-script`
   - ห้ามส่งงานโดยแค่แนบตารางคำให้ผู้ใช้ไปฟังเอง
   - วิธีหาคำสะกดและตารางคำที่ทดสอบแล้วอยู่ในสกิล `/lumina-script` หัวข้อ "ตรวจเสียงที่ได้"
6. **จับเวลา** `python <skill_dir>/scripts/align.py <proj> <voice>` ต้องได้ ratio เกิน 0.8 และ unmatched ใกล้ 0 บรรทัดที่ขึ้นว่าฉากค้างเกิน 15 วินาทีให้แตกฉากเพิ่ม (ลบ `asr.json` ก่อนทุกครั้งที่เปลี่ยนไฟล์เสียง)
7. **ภาพนิ่งตรวจ** `python <skill_dir>/scripts/render_range.py <proj> shots <proj>/chk <เวลา...>` แล้วต่อเป็นแผ่นเดียวด้วย ffmpeg `tile` เปิดดูว่าตัวหนังสือไม่ล้นกรอบ
8. **เพลง** ตามหัวข้อ "เพลงประกอบ" แล้ว `python <skill_dir>/scripts/mix.py <proj> <voice> 12 <เพลง...>` (ไม่ใส่เพลงก็ได้ ถ้าผู้ใช้บอกไม่เอา BGM)
9. **เรนเดอร์** แบ่ง 3 ช่วงเฟรมรันพร้อมกันด้วย `run_in_background` แล้ว concat (คลิป 266 วินาทีใช้ราว 9 นาที)
10. **ประกบ** `ffmpeg -i silent.mp4 -i <proj>/master.wav -c:v copy -c:a aac -b:a 192k -shortest -movflags +faststart out.mp4` (`master.wav` ถูกปรับเป็น -14 LUFS แล้ว)
11. **ตรวจไฟล์จริง** ความยาว จำนวนเฟรม ความดัง และดึงเฟรม 10 จุดรวมรอยต่อระหว่างช่วงมาเปิดดู แล้วรายงานตามหัวข้อ "รายงาน"
12. **ปก** ด้วยสกิล `/clipcover` ทำทุกคลิปโดยไม่ต้องรอผู้ใช้ขอ คลิปเรื่องเทคนิคที่ไม่มีภาพเสรีเด่น ๆ ให้วาดภาพประกอบเองด้วย HTML (`clipcover/scripts/art_to_png.py`)
13. **ข้อความโพสต์** เขียน `<proj>/caption.txt` (Facebook) และ `<proj>/youtube.txt` (TITLE + DESCRIPTION) ตามรูปแบบในสกิล `/reelpost` ทำไว้รอเลย
14. **โพสต์** เฉพาะเมื่อผู้ใช้สั่งในเทิร์นนั้น ใช้สกิล `/reelpost` (ทำไฟล์อัปไม่เกิน 10 MB, YouTube + Facebook, ตั้งเวลาเวลาไทย)

## clip.json

```json
{ "head": 0.4, "tail": 1.4,
  "show": [["คล็อดโค้ด", "Claude Code"], ["คล็อด", "Claude"], ["สามทาง", "3 ทาง"]],
  "lines": [
    { "id": 1, "scene": { "type": "title", "a": "Claude Code", "b": "Mods", "c": "ปรับแต่งจากข้างใน" },
      "say": "ตอนนี้ทำได้แล้วนะครับ|ของใหม่ตัวนี้ชื่อว่า|*ม็อด*" } ] }
```

- `say` คือสิ่งที่เสียงพูดจริง เขียนเป็นคำอ่าน (คำอังกฤษเป็นคำอ่านไทย ตัวเลขเป็นคำ) คั่นวลีด้วย `|` ครอบวลีสำคัญด้วย `*...*`
- `show` แปลงคำอ่านกลับเป็นคำที่ขึ้นจอ เรียงคำยาวก่อนคำสั้น (`คล็อดโค้ด` ก่อน `คล็อด`)
- ถ้าใช้ Lumina บทที่ส่งให้ Lumina กับ `say` ต้องเป็นถ้อยคำเดียวกัน ต่างกันได้แค่แท็กและคำเอ่อ

**ซับ (แบบที่ผู้ใช้ชี้ให้ทำตาม 11 ต.ค. 2026):** ทีละวลีสั้นบรรทัดเดียว 2 ถึง 5 คำ ตัดตามความหมาย ไม่ใช่ตามความยาว ตัวขาวหนาขอบดำ อยู่ช่วงบนของจอ ตัดฉับไม่เด้ง วลีสำคัญสีเหลืองตัวใหญ่ วลีละไม่เกินราว 26 ตัวอักษร ตัวเอนจินทำหน้าตาให้แล้ว หน้าที่ของคนเขียนคือแบ่งวลีให้ดี

**ซับแบบสองบรรทัด** (แบบคลิปตัวอย่างที่ผู้ใช้ส่ง 16 ต.ค. 2569): บรรทัดเล็กบน ใหญ่ล่าง คำสำคัญสีเหลืองมะนาว เงานุ่ม อยู่ช่วงล่างกลางจอ ใช้ `scenes.html` ของ `$WORK/tmp/vectordb-reel` เป็นต้นแบบ ใน `say` ใช้ ` / ` แบ่งบรรทัด และ `[คำ]` เน้นคำ ซ่อนซับเองในฉาก `cta` ไฟล์เดียวกันมีฉาก `rank` (การ์ดอันดับ แถบคะแนน 3 ด้าน) สำหรับคลิปจัดอันดับ

**ชนิดฉาก** (`scene.type`) ดูช่องที่ต้องใส่ใน `references/scenes.md`: title, stamp, num, rule, list, cards, flow, chat, strike, warn, formula, loop, cmds, term, phone, cta และชุดกลโกง videocall, ad, profile, sms
ต้องการธีมสีอื่นหรือชนิดฉากใหม่ ให้ก๊อป `scripts/scenes.html` ไปไว้ใน `<proj>/scenes.html` แล้วแก้ที่นั่น ตัวเรนเดอร์จะหยิบฉบับของโปรเจกต์ก่อน

## เสียงพากย์

| ทาง | เมื่อไร | ทำอย่างไร |
|---|---|---|
| 1 Lumina เสียง "โกสินทร์3" (เสียงหลัก ผู้ใช้ยืนยัน 18 ต.ค. 2569) | ผู้ใช้ขอเสียงธรรมชาติ มีอารมณ์ หรือเอ่ยถึง Lumina | เขียนบทด้วยสกิล `/lumina-script` (ภาษาพูด + แท็ก) ย่อหน้าละหนึ่งฉาก ส่งผ่านแท็บ Chrome ตามสกิลนั้น หรือ `$PROJECTS/lumina-bridge` เมื่อผู้ใช้ล็อกอินในโปรไฟล์ของ bridge แล้ว |
| 2 edge-tts + RVC | ดีฟอลต์ ฟรี ไม่ต้องใช้เบราว์เซอร์ | `python <skill_dir>/scripts/tts_lines.py <proj>` ได้ `narr_src.wav` แล้ว `bash /d/tmp/voiceclone/voice_kosin.sh <proj>/narr_src.wav <proj>/narr_kosin.m4a > <proj>/voice.log 2>&1` เก็บ log เต็ม ห้าม pipe เข้า tail แล้วเช็กว่าไฟล์เกิดจริง |

- Lumina: ตัวตรวจของ `/lumina-script` ประเมินความยาวต่ำไป บท 2,715 ตัวอักษร (ไม่นับแท็ก) ได้เสียงจริง 264 วินาที ราว **10 ตัวอักษรต่อวินาที** อยากได้คลิป 90 วินาทีให้เขียนไม่เกิน 900 ตัวอักษร และบอกผู้ใช้ก่อนกดสร้างถ้าจะยาวเกิน 2 นาที
- Lumina เครดิตฟรีใช้ได้กับงานไม่เชิงพาณิชย์ และข้อตกลงห้ามบอต บอกผู้ใช้ทุกครั้ง
- ผู้ใช้ขอ "ลด reverb": ตัว dereverb สองรุ่น (UVR-DeEcho-DeReverb, mel-band roformer) ดึงอะไรออกไม่ได้เลยกับเสียง Lumina อย่าเสียเวลารันซ้ำ ใช้ EQ กับตัดหางเสียงแทน:
  `highpass=f=90,equalizer=f=280:t=q:w=1.1:g=-4,equalizer=f=550:t=q:w=1.4:g=-2,equalizer=f=4500:t=q:w=1.0:g=2,agate=threshold=0.03:ratio=2.5:attack=4:release=110:range=0.2:knee=4`
  ถ้ายังก้อง ต้นเหตุคือเสียงต้นแบบที่ใช้โคลน ต้องอัดใหม่ในที่เก็บเสียง

## เพลงประกอบ

- **เพลงประจำคลิปบรรยาย (ค่าเริ่มต้น):** `$MEDIA\bgm\Kosin Explainer Bed - Suno.wav` 122 วินาที สร้างด้วย Suno (แพ็ก Pro) ผู้ใช้สั่งเมื่อ 15 ต.ค. 2569 ให้ใช้กับทุกคลิปบรรยายแบบนี้ ไม่ต้องสั่ง Suno ใหม่ ถ้าคลิปยาวเกิน 122 วินาทีให้ส่งไฟล์เดิมซ้ำสองครั้งเข้า `mix.py` ให้ครอสเฟดต่อ ระดับที่ผู้ใช้ฟังแล้วคือเบากว่าเสียงพากย์ 11 dB

- เช็กโควตาดาวน์โหลด Suno ก่อน: `cd $PROJECTS/suno-bridge && node probe-dl.mjs <clipId เก่า>` ถ้าเจอ "Out of Downloads" ใช้เพลงจาก `$MEDIA\bgm` แล้วบอกผู้ใช้
- สั่งเพลง: `node create.mjs --instrumental --styles "<แนวเพลงภาษาอังกฤษ>, no vocals" --title "<ชื่ออังกฤษ>" --dry` ก่อน แล้วรันจริงพร้อม `--outdir <proj>/bgm` ได้ 2 เทค
- เทคหนึ่งยาวราว 2 ถึง 2.5 นาที คลิปยาวกว่านั้นให้ส่งทั้งสองเทคเข้า `mix.py` มันต่อด้วยครอสเฟดให้ แล้วบอกผู้ใช้ว่ารอยต่ออยู่ตรงไหน
- **ระดับเพลง: เริ่มที่เบากว่าเสียงพากย์ 12 dB** ผู้ใช้เคยบอกว่า 17 และ 27 dB ไม่ได้ยินเพลงเลย ถ้าไม่แน่ใจให้ทำสองระดับ (12 กับ 16) ให้เลือก การผสมใหม่ไม่ต้องเรนเดอร์ภาพซ้ำ
- วัดระดับเสียงพากย์โมโนต้องแปลงเป็นสเตอริโอก่อนวัด LUFS ไม่งั้นอ่านต่ำไป 3 dB · เพลงเปียโนหรือเครื่องสายย่านต่ำให้ใส่ `highpass=f=110,equalizer=f=2500:t=q:w=1.0:g=3.5` ที่สายเพลง ไม่งั้นหายบนลำโพงมือถือ (คลิป Unshatter 11 ต.ค. 2569 ตั้งที่ 10 dB)
- Suno หมดโควตาและคลังไม่มีเพลงที่เข้าโทน: ใช้ YouTube Audio Library ใน Studio ของผู้ใช้ ดู `~/.claude/skills/vidcraft/references/reel-lessons.md` ข้อ 6
- เพลงเป็นโครงเรื่องได้: ช่วงเล่าเงียบหรือเบามาก แล้วเข้าเต็มตอนอารมณ์พลิกหรือช่วงสรุป ไม่จำเป็นต้องปูทั้งคลิป

## รายงาน

- ผมฟังเสียงไม่ได้ ต้องบอกทุกครั้งว่าน้ำเสียง การออกเสียงคำทับศัพท์ และเพลง ยังไม่มีใครฟัง
- คำที่ตัวถอดเสียงได้ยินไม่ตรงบทต้องแก้ไปแล้วในขั้น 5 รายงานว่าแก้คำไหนเป็นคำสะกดอะไร และจุดที่เหลือเป็นแค่การสะกดต่างของตัวถอดเสียง (เช่น Pack กับ แพ็ก) พร้อมเวลา
- ให้ path เต็มของไฟล์คลิปในบรรทัดของตัวเอง ผู้ใช้ถามหา path บ่อย
- บอกแหล่งข้อมูล ความยาว ความดัง และสิ่งที่ต่างจากที่ขอ

## กับดัก

- ข้อความไทยห้ามส่งผ่าน argument ของ Git Bash ให้เขียนไฟล์ด้วย Write หรือ python
- heredoc ยาวที่มี backtick พังใน Git Bash ให้เขียนสคริปต์เป็นไฟล์
- `.fit` ย่อฟอนต์อัตโนมัติถึง 30px คำสั่งยาวเกิน 24 ตัวอักษรจะเล็กจนอ่านยาก ให้แตกเป็นสองบรรทัดในฉาก `term`
- ฟอนต์ตัวพิมพ์ (Consolas) ใช้กับอังกฤษเท่านั้น ห้ามมีอักษรไทยในบรรทัดของ `term` และ `cmds`
- งานเบื้องหลังที่เกิน 10 นาทีถูกตัด ให้แบ่งเรนเดอร์เป็นช่วง
- เศษท้ายไฟล์ที่ whisper แต่งขึ้นเอง (0.4 วินาทีสุดท้าย) `align.py` ตัดทิ้งให้แล้ว อย่าตีความว่าเสียงมีคำเกิน
- บทเรียนรวมเรื่องกะความยาว transition ซับ และ remaster เสียง อยู่ที่ `~/.claude/skills/vidcraft/references/reel-lessons.md`
- ความยาวจากเสียงซ้อม edge-tts ใช้บอกผู้ใช้ไม่ได้ Lumina ช้ากว่าราว 30% (บท 1,270 ตัวอักษร ซ้อมได้ 94 วินาที เสียงจริง 123 วินาที)
- ฉาก `rule` ตัด `title` เป็นสองบรรทัดตรงเว้นวรรคแรก ถ้ามีป้าย 3 ใบ ใบที่สามจะล้นการ์ดลงไปทับป้าย "บรรยายโดย" ให้ใช้เว้นวรรคแบบไม่ตัดบรรทัด (` `) ใน `title` หรือใช้ป้าย 2 ใบ
- ฉาก `num` ช่อง `top` กับ `unit` ไม่ย่อฟอนต์เอง ข้อความยาวให้ครอบด้วย `<span class=\"fit\" data-w=\"980\">...</span>` ใน clip.json
- คลิปยาวกว่าเพลงประจำ 122 วินาทีนิดเดียว (เช่น 126 วินาที) รอยครอสเฟดของเพลงจะตกช่วงฉากปิดราววินาที 118 บอกผู้ใช้ตำแหน่งนั้น
- เสียงพากย์ Lumina ให้ใช้พอร์ตของงานตัวเองเสมอ ดูเหตุพอร์ตชนในสกิล `/lumina-script` ข้อ 5
- หน้า Lumina ไม่แสดงรายชื่อเสียง: ใช้รหัสที่เบราว์เซอร์จำไว้ได้ แต่หลังได้เสียงให้รัน `lumina-script/scripts/voice_check.py <เสียง>` ต้องใกล้กลุ่มโกสินทร์3 ชัดเจน
- `python -I` ไม่อ่าน `PYTHONIOENCODING` พิมพ์อักษรไทยแล้วล้มด้วย cp1252 สคริปต์ที่พิมพ์ไทยให้ใส่ `sys.stdout.reconfigure(encoding="utf-8")` เอง
- งานหลายเซสชันพร้อมกัน: อีกเซสชันอาจใช้ chatgpt-bridge, พอร์ต, แท็บ Chrome หรือแก้สกิลเดียวกันอยู่ อ่านไฟล์สกิลก่อนแก้ทุกครั้งและแก้แบบแทรกจุดเล็ก ไม่เขียนทับทั้งไฟล์

## กฎความเร็วเสียงโกสินทร์3 (ผู้ใช้สั่ง 21 ต.ค. 2569)
เสียง "โกสินทร์3" ทุกคลิปต้อง**เร็วขึ้น 8%** หลังได้ไฟล์จาก Lumina ให้เร่งด้วย ffmpeg `-af atempo=1.08` (เสียงไม่แหลม) ก่อน align และ mix ไม่ใช้แท็ก `@ความเร็ว=0.8` เสียงอื่น (เช่น ลินดา) คงความเร็วเดิม
เหตุผล: คนดูบ่นว่าพูดช้า ผู้ใช้ฟังเทียบ 1.00 / 1.08 / 1.15 แล้วเลือก 1.15 ก่อน จากนั้นเปลี่ยนเป็น 1.08 (เร็วขึ้น 8%) วันเดียวกัน
ตัวอย่าง: `ffmpeg -i vo.mp3 -af atempo=1.08 vo_fast.wav` แล้วใช้ไฟล์เร่งแล้วในขั้นต่อไปทั้งหมด (ตรวจคำเพี้ยนด้วยไฟล์ที่เร่งแล้ว)
