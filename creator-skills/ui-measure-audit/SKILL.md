# ui-measure-audit

รีวิว UI ด้วยตัวเลข ไม่ใช่ความรู้สึก ใช้ก่อนบอกว่างาน UI เสร็จ หรือเมื่อ skill ออกแบบ (เช่น prom-design) ขอให้วัดแต่สคริปต์ของมันไม่ได้มาด้วย

## สิ่งที่วัด

ต่อหน้า ต่อความกว้าง (320, 375, 768, 1280, 1440):

| ค่า | วัดอย่างไร | เกณฑ์ |
|---|---|---|
| screens | `scrollHeight / innerHeight` | หน้าเครื่องมือบนมือถือ: ไม่เกิน 3 ดี, เกิน 4.5 คือยาวไป |
| overflowX | `scrollWidth - innerWidth` | ต้องเป็น 0 |
| เป้าแตะ | ปุ่ม ลิงก์ ช่องกรอก แถวที่กดได้ ที่สูงหรือกว้างน้อยกว่า 44px | ต้องไม่มี |
| ข้อความไทยมี letter-spacing | `getComputedStyle().letterSpacing > 0` บนข้อความที่มีอักษรไทย | ต้องไม่มี |
| ขีดยาว | อักขระ U+2013 / U+2014 ในข้อความที่แสดง | ตามกฎของงานนั้น |
| ข้อความถูกตัด | `scrollWidth > clientWidth` บนองค์ประกอบที่ `overflow: hidden` | ดูทีละจุดว่าตั้งใจหรือไม่ |
| console error | ทุกการเปิดหน้า | ต้องไม่มี |
| contrast | ถ่ายภาพเฉพาะกรอบขององค์ประกอบ แล้วคำนวณจากพิกเซล | 4.5:1, หรือ 3:1 เมื่อ 24px ขึ้นไป |

contrast คิดจากพิกเซลจริง: พื้น = สีที่พบมากที่สุดในกรอบ, ตัวอักษร = พิกเซลที่ต่างจากพื้นมากที่สุด วิธีนี้ใช้ได้กับข้อความบนพื้นโปร่งแสง บน canvas และบนรูป ซึ่งค่าจาก CSS บอกไม่ได้

## ขั้นตอน

1. คัดลอก `scripts/ui-audit-example.cjs` ไปไว้ในโฟลเดอร์ชั่วคราวของงาน (ไม่ใช่ใน repo ของลูกค้า)
2. แก้สามส่วนในไฟล์ให้ตรงกับงาน:
   - `base` = URL ของเซิร์ฟเวอร์ที่รันอยู่
   - `pages` = แต่ละหน้าที่จะตรวจ พร้อม `login` (ขั้นตอนเข้าสู่ระบบด้วย selector จริง) และ `data` (selector ของเนื้อหาที่มาจากข้อมูล ซึ่งไม่นับเป็นข้อความของหน้า)
   - รายการ selector ที่จะวัด contrast ของแต่ละหน้า
3. รัน `node ui-audit.cjs` จะได้ตารางค่าต่อหน้าต่อความกว้าง รายละเอียดที่ 375px และบรรทัด `pass` / `FAIL` ของ contrast
4. เปิดภาพใน `audit/` ดูด้วยตา: ตัวเลขจับการซ้อนทับและของที่ถูกตัดไม่ได้ทั้งหมด
5. แก้ แล้วรันซ้ำจนค่าผ่าน รายงานเป็น "ก่อน → หลัง" พร้อมตัวเลข

## สิ่งที่ต้องมี

- Node 18 ขึ้นไป และ Playwright ที่ติดตั้งอยู่แล้ว สคริปต์ตัวอย่างอ้าง `$WORK/pwtest/node_modules/playwright` และ `playwright-core/lib/utilsBundle` (ใช้ตัวถอดรหัส PNG ที่มากับ Playwright ไม่ต้องลงแพ็กเกจเพิ่ม)
- ระบุ `executablePath` ของ Chromium ที่ดาวน์โหลดไว้แล้วตรง ๆ ถ้า `chromium.launch()` เปล่า ๆ หาเบราว์เซอร์ไม่เจอ

## ข้อควรระวังที่เจอจริง

- **contrast อ่านค่าต่ำผิดได้** เมื่อองค์ประกอบอยู่ใต้ overlay อยู่นอกจอบางส่วน หรือ selector จับ span ชั้นนอกที่มีแถบสีอยู่ข้างใน ค่าที่ต่ำผิดปกติให้ตรวจซ้ำด้วย `getComputedStyle` ของตัวอักษรกับพื้นจริงก่อนสรุปว่าเป็นข้อบกพร่อง
- **วัดหลังล็อกอินจริง** ถ้ายังติดหน้าล็อกอิน ทุกอย่างข้างหลังจะถูกวัดผ่านฉากมืด
- **ภาษามีผล** ข้อความอังกฤษยาวกว่าไทยในบางจุด หน้าเดียวกันล้นจอเฉพาะภาษาอังกฤษได้ ตรวจทั้งสองภาษาเมื่อหน้ารองรับสองภาษา (ตั้ง `locale` ของ context)
- **grid สองคอลัมน์ล้นจอ** เมื่อเนื้อหาข้างในห้ามตัดบรรทัด: ใช้ `minmax(0, 1fr)` และ `min-width: 0` ที่ลูก
- **อย่ารันพร้อมงานที่วัดเวลา** เบราว์เซอร์แย่ง CPU ทำให้ตัวเลขเวลาของงานอื่นเพี้ยน

## ขอบเขตที่ทดสอบแล้ว

รันจริงเมื่อ 12 ต.ค. 2026 กับหน้า `/brain` และ `/dashboard` ของโปรเจกต์ panya บน Windows สคริปต์ที่แนบเป็นฉบับที่ใช้กับโปรเจกต์นั้นตรงตัว (เส้นทาง selector และการอ่าน API key จาก `.env` ของ panya ยังอยู่ในไฟล์) การนำไปใช้กับโปรเจกต์อื่นต้องแก้ตามขั้นตอนข้อ 2 และยังไม่เคยรันกับโปรเจกต์อื่น
