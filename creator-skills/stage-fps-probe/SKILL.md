# /stage-fps-probe

ใช้ก่อนบอกใครว่าหน้าเว็บ 3 มิติลื่น โดยเฉพาะงานขึ้นเวทีหรือจอใหญ่

## ทำไมต้องมี

บนเครื่องนี้ (Iris Xe, Windows 11, Chrome 156) ตัวเลขจาก Playwright เชื่อไม่ได้ทั้งสองทาง:
- หน้าต่างที่ถูกบังรายงาน 60 fps ทั้งที่ไม่ได้ขึ้นจอจริง
- Chrome ที่ Playwright เปิด พอขึ้นหน้าสุดจริงอาจเหลือ 1 fps พอดี (ช่วงห่าง 1016 ms นิ่ง) ทั้งที่ Chrome ปกติกับหน้าเดียวกันได้ 58 ถึง 60 fps

ช่วงห่าง 1016 ms ที่นิ่งแบบนี้ไม่ใช่เครื่องวาดไม่ทัน ถ้าเครื่องไม่ทันจะแกว่ง ยังไม่รู้กลไก
`page.screenshot` ก็ค้างเหลือราว 1 ครั้งต่อวินาทีในสภาพเดียวกัน ถ้าต้องอัดเฟรม ให้อ่านจาก canvas ตรง ๆ (`drawImage` ลง `OffscreenCanvas` แล้ว `convertToBlob`)

## ขั้นตอน

เครื่องมืออยู่ใน `~/.claude/skills/stage-fps-probe/scripts/` ต้องมี Chrome ปกติและโฟลเดอร์ที่มี `node_modules` ของ playwright (ชี้ด้วยตัวแปร `$CHATGPT_BRIDGE` ใช้ playwright แค่ต่อ CDP อ่านตัวเลข) ถ้า Chrome ไม่ได้อยู่ที่ path มาตรฐานให้ตั้ง `CHROME_PATH`

1. **เช็กว่าเครื่องว่างก่อนเสมอ** โหมด `front` ยึดทั้งจอและแย่งคีย์บอร์ด เคยทับหน้าต่าง Teams ของผู้ใช้มาแล้ว

   ```bash
   powershell -NoProfile -ExecutionPolicy Bypass -File scripts/idle.ps1   # idle=12s fg=<ชื่อหน้าต่าง>
   bash scripts/wait-idle.sh 30        # รอจนไม่มีการใช้งาน 30 วินาทีและจอไม่ล็อก
   ```

2. **ลองแบบไม่รบกวนก่อน** โหมด `tile` เปิดหน้าต่างเล็กมุมจอ อยู่บนสุดแต่ไม่แย่งโฟกัส

   ```bash
   READY='window.__ready === true' node scripts/probe.mjs test tile "http://127.0.0.1:8875/page"
   ```

3. **วัดสภาพจริง** ใช้ flag เดียวกับที่จะใช้บนเวที และรันเมื่อเครื่องว่างเท่านั้น

   ```bash
   bash scripts/wait-idle.sh 30 && POS=0,0 WIN=1536,960 node scripts/probe.mjs stage front "<url>" --start-fullscreen
   ```

   ถ้าจะหยุดรอการใช้งานระหว่างรัน ให้รันเป็นงานเบื้องหลังผ่าน Bash `run_in_background` ไม่ใช่ `nohup ... &` เพราะ shell ปิดแล้วงานตาย

4. อ่านผล 1 บรรทัด JSON

   | ช่อง | ความหมาย |
   |---|---|
   | `fps` `med` `max` | เฟรมต่อวินาที ค่ากลาง และช่วงห่างยาวสุด (ms) |
   | `vis` `inner` `dpr` | ต้องเป็น `visible` และขนาดตรงจอที่ตั้งใจ |
   | `read` | ค่าที่ขอผ่าน env `READ` เช่น ความละเอียดบัฟเฟอร์ |

   env อื่น: `SECS` (ค่าเริ่มต้น 5), `POS`, `WIN`, `READY`, `READ`

5. **รอบเดียวไม่พอ** วัดอย่างน้อย 2 รอบ แยกแบบมีและไม่มีงานเสริม (เช่นจับมือ) และบอกเงื่อนไขทุกครั้งที่รายงาน: จอไหน วัดกี่วินาที ใช้กล้องปลอมหรือจริง

## เงื่อนไขที่ต้องบอกตามจริง

- วัดบนจอโน้ตบุ๊กไม่เท่ากับจอใหญ่จริง เพราะ compositor ต้องทำงานตามขนาดจอ ต้องวัดซ้ำที่สถานที่
- ถ้าเจอ 1 fps ให้ลองบน `probe.mjs` ก่อนสรุปว่าโค้ดพัง ถ้าเกิดเฉพาะ Playwright ให้ถือว่าเป็นอาการของเครื่องมือ
- `--use-file-for-fake-video-capture` ทำให้ Chrome ขึ้นแถบเตือนบน เนื้อที่หน้าจอจะเล็กลงเล็กน้อย (เห็น `inner` สูงลดลง) ไม่ใช่ปัญหาของหน้าเว็บ
