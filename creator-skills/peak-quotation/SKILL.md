# peak-quotation

ทำใบเสนอราคาใน PEAK ผ่าน Playwright ที่เกาะหน้าต่าง Chromium ซึ่งผู้ใช้ล็อกอินไว้ ใช้จริงแล้ว สคริปต์ทุกตัวใน `scripts/` คือตัวที่รันในงานนั้น ต่างกันแค่ค่าตัวอย่างใน `fill.js`
รหัส business (`emi`), รหัสลูกค้า และรหัสสินค้าของแต่ละกิจการให้จดไว้เองในโน้ตของคุณ

## ถามผู้ใช้ให้จบในครั้งเดียวก่อนเริ่ม
บริษัทผู้ขาย (ถ้ามีหลายกิจการใน PEAK) · ราคาก่อนหรือรวม VAT · แยกรายการแบบไหน · เงื่อนไขการชำระเงิน
ตัวเลขเชิงพาณิชย์ห้ามเดา เงื่อนไขที่ใส่เองให้บอกผู้ใช้ในสรุป

## ขั้นตอน (cwd = โฟลเดอร์ scripts ของสกิลนี้ หรือคัดลอกไป scratchpad)
1. เปิดหน้าต่าง: `node launch.js` แบบ background (เปิด CDP ที่ `127.0.0.1:9222` ห้ามใช้ `localhost`)
   แล้ว `node peek.js "" 6000` ดูว่ายังล็อกอินอยู่ไหม ถ้าเจอหน้า "เข้าสู่ระบบ PEAK" ให้ผู้ใช้ล็อกอินเองในหน้าต่างนั้น ห้ามขอรหัสผ่าน
2. ผู้ใช้อาจเปิดเอกสารอื่นค้างไว้ในแท็บอื่น **ห้ามแตะ** สคริปต์ทุกตัวเปิดแท็บใหม่เอง
3. เช็คซ้ำ: `node list.js "<ชื่อลูกค้า>"` ดูใบเสนอราคาเดิมของลูกค้านั้น (อ่านอย่างเดียว)
4. หาลูกค้าและสินค้าในหน้าสร้าง: ต้องมีแท็บ create เปิดอยู่ก่อน (รัน `fill.js` ครั้งแรกด้วยค่าตัวอย่างก็ได้ เพราะยังไม่บันทึก)
   ‼ `peek.js <url>` จะพาแท็บ PEAK แท็บแรกไปที่ url นั้น ใช้เมื่อไม่มีเอกสารอื่นของผู้ใช้เปิดอยู่เท่านั้น แล้ว
   `node search.js customer "<คำค้น>"` และ `node search.js product P000 "<รหัสสินค้าที่ขึ้นต้นของคุณ>" "<คำขึ้นต้นชื่อ>"`
   ช่องค้นหาสินค้าเจอเฉพาะ **ชื่อที่ขึ้นต้นด้วยคำนั้น หรือรหัส** ไม่ใช่คำกลางชื่อ
5. แก้ค่าด้านบนของ `fill.js` (EMI, CUSTOMER, ROWS, NOTE) แล้ว `node fill.js` สคริปต์จะปิดแท็บ create เดิมโดยไม่ถาม เปิดแท็บใหม่ กรอก แล้วพิมพ์ค่าที่อ่านกลับ + `filled.png`
   **ยังไม่บันทึก** ตรวจยอด `net` / `total` กับภาพก่อน
6. `node save.js` กด `บันทึกร่าง` แล้วพิมพ์ URL หน้า edit (มี `eii=`)
7. ยืนยันด้วย `node verify.js "<edit url>"` เปิดเอกสารในแท็บใหม่ อ่านทุกบรรทัด หมายเหตุ ยอดรวม แล้วปิดแท็บ

## กับดัก (เจอจริงทั้งหมด)
- **ห้ามกด `อนุมัติใบเสนอราคา`** เว้นแต่ผู้ใช้สั่งในเทิร์นนั้น
- @playwright/mcp อัปเดตแล้วหา chromium รุ่นของตัวเองไม่เจอ: ถ้า Playwright หา Chromium ของตัวเองไม่เจอ ให้ตั้ง env `CHROMIUM_PATH` ชี้ไป Chromium/Chrome ที่มีอยู่ (และ `PLAYWRIGHT_MODULE` ชี้ไปโมดูล playwright ถ้าไม่ได้ติดตั้งแบบปกติ, `PEAK_PROFILE` = โฟลเดอร์โปรไฟล์ที่เก็บล็อกอิน)
- หน้า create/edit มี beforeunload: `page.reload()` ทำ Playwright พัง ("No dialog is showing") ให้ `page.close({runBeforeUnload:false})` แล้วเปิดแท็บใหม่แทน
- `browser.close()` หลัง `connectOverCDP` ฆ่าหน้าต่างของผู้ใช้ ให้จบสคริปต์ด้วย `process.exit(0)` เฉย ๆ
- ข้อความไทยใน PEAK ใช้ `เเ` (สระเอสองตัว) แทน `แ` ต้อง normalize ก่อนเทียบทุกครั้ง
- เลือกสินค้าแล้วราคาถูกรีเซ็ตเป็นค่าของสินค้า และชื่อสินค้าถูกเติมในคำอธิบาย จึงต้องกรอกราคาและคำอธิบาย **หลัง** เลือกสินค้า
- ปุ่มเพิ่มแถวเป็น `<button>` ที่มี `<i>` อยู่ข้างใน หาด้วย `button` ที่ innerText ตรง ไม่ใช่ leaf element
- textarea ตั้งค่าผ่าน native value setter + `input`/`change`/`blur` (Vue จึงเห็นค่า) ช่องหมายเหตุลูกค้าคือ `textarea#หมายเหตุสำหรับลูกค้า` จำกัด 1,000 ตัวอักษร (`fill.js` เช็คให้)
- ป้าย VAT อ่านด้วย regex ไม่ได้ ให้ดู `มูลค่าที่คำนวณภาษี 7%` กับ `จำนวนเงินทั้งสิ้น` แล้วคำนวณเทียบ
- หน้าต่างแชต Intercom บังปุ่ม สคริปต์ซ่อนให้แล้ว
- ช่องค้นลูกค้าในบางกิจการ (เจอในบางกิจการ) ซ่อน input ไว้จนกว่าจะคลิกกรอบ `fill.js` จึงคลิกกรอบด้วยตำแหน่งแล้วพิมพ์ด้วยคีย์บอร์ด
- ลูกค้าใหม่: เลือก "เพิ่มผู้ติดต่อ" ในช่องค้นลูกค้า ใส่เลขทะเบียน 13 หลักแล้วกด `ค้นหา` PEAK ดึงชื่อ สาขา ที่อยู่จากกรมพัฒนาฯ ให้ ตรวจกับแหล่งอื่นก่อนกด `เพิ่ม`
- สินค้าใหม่: "เพิ่มสินค้า/บริการ" ในช่องสินค้าของแถว เลือกประเภท `บริการ` (placeholder ชื่อเปลี่ยนเป็น "ชื่อบริการที่ปรากฎ...") ต้องเลือกหน่วยด้วยการคลิกกรอบตามตำแหน่ง บัญชีขายตั้งให้เป็น 410201 รายได้จากการให้บริการ
- **ห้ามกด Escape ในหน้าต่างเพิ่มสินค้า/ผู้ติดต่อ** มันปิดหน้าต่างทิ้งโดยไม่บันทึก
- หน้าต่างเพิ่มสินค้า: **เลือกประเภท `บริการ` ก่อนพิมพ์ชื่อ** เพราะเปลี่ยนประเภทแล้วช่องชื่อถูกล้าง คลิกที่วงกลมของ radio (ห่างป้ายราว 15 px ทางซ้าย) คลิกที่ป้ายเฉย ๆ ไม่เปลี่ยน ตรวจด้วย `input[type=radio]` ว่า checked จริง · หน่วยที่ไม่มีในรายการ: เปิดช่องหน่วยแล้วเลือก `เพิ่มหน่วยสินค้า` ได้หน้าต่างย่อย เลือกประเภทบริการ ใส่ชื่อ TH/EN แล้วกด `+ เพิ่มหน่วยใหม่` จากนั้นพิมพ์ชื่อหน่วยในช่องหน่วยเพื่อค้นแล้วคลิกเลือก (ทดสอบจริงแล้ว)
- ยืนราคาเกิน 7 วัน: ตั้ง `VALID_UNTIL` ใน `fill.js` ('dd/mm/yyyy') สคริปต์พิมพ์ทับช่องวันที่ช่องที่สองแล้วคลิก (60, 600) ปิดปฏิทิน ตรวจใน read-back ช่อง `dates`
- แก้ใบร่างที่บันทึกแล้ว (หน้า `quotationDetail?...&eii=`): ปุ่ม "บันทึก" ในแถบล่างเป็น `div` ไม่ใช่ `<button>` และหน้ามีแถบปุ่มสองชุด (ชุดหนึ่งอยู่นอกจอ) ให้หา `p` ที่ข้อความตรง "บันทึก" และอยู่ในจอ แล้วคลิกตามตำแหน่ง ปุ่ม "อนุมัติใบเสนอราคา" อยู่ติดทางขวา ต้องเช็คว่าจุดคลิกอยู่ซ้ายของมัน

- `list.js` อ่าน EMI จาก env `PEAK_EMI` (ค่า `emi=` ใน URL ของ PEAK) ถ้าไม่ตั้ง ค้นไม่เจอแม้ลูกค้ามีใบเดิม
- คลิกเลขที่เอกสารในหน้ารายการ PEAK เปิดเอกสารใน **แท็บใหม่** (`quotationDetail?uuid=...`) URL ของแท็บรายการไม่เปลี่ยน อ่านจากแท็บใหม่แล้วปิดเอง
- วันที่ใช้ได้ถึง ค่าตั้งต้นคือ 7 วัน ถ้าหมายเหตุเขียนยืนราคา 30 วันต้องแก้ช่องนี้ด้วย พิมพ์ทับในช่องวันที่ได้ แล้วคลิกที่ขอบหน้าจอว่าง (x≈60) เพื่อปิดปฏิทิน **อย่าคลิกในกรอบฟอร์ม** เคยไปโดนช่องลูกค้าจนเมนูเลือกลูกค้าเปิดค้าง (ค่าที่เลือกไว้ไม่หาย แต่ต้องเช็ค)
- `save.js` ไม่ reload แล้ว (เคยพังด้วย "No dialog is showing" ทุกครั้งหลังบันทึก) ตรวจผลด้วย `verify.js` อย่างเดียว
