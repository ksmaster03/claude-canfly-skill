# promotioncut

[English](README.md) · **ภาษาไทย**

![คลิปโปรโมตในกรอบ วางคู่กับแถบฟิล์มที่รอยตัดตรงกับเส้นจังหวะของคลื่นเสียง](docs/promotioncut-hero.jpg)

สกิลของ Claude Code สำหรับทำคลิปโปรโมตงานหรือสินค้าแบบสี่เหลี่ยมจัตุรัส (1080x1080) ฟุตเทจตัดเร็วเล่นอยู่ในช่องที่กินพื้นที่ 52.5% ของเฟรม รอบช่องเป็นกรอบแบรนด์นิ่งที่มีพาดหัว วันที่ สถานที่ และปุ่ม CTA ส่วนเสียงเป็นเพลงบรรเลงล้วน

ตำแหน่งคัตเขียนเป็นเลขบีต ไม่ใช่วินาที ตัวประกอบคลิปจะแปลงบีตเป็นเฟรมให้เอง คัตจึงลงกริดของเพลงตั้งแต่โครงสร้าง จากนั้นตัวตรวจจะวัดไฟล์ที่ได้จริงเพื่อพิสูจน์อีกชั้น

## ทำอะไรได้บ้าง

- วัดเพลง: เทมโป จังหวะที่หนึ่งแรก และตารางห้องที่บอกว่า drop กับเบรกอยู่ตรงไหน
- เรนเดอร์กรอบและการ์ดจากเทมเพลต HTML ด้วย headless Chromium ข้อความไทยจึงจัดสระและวรรณยุกต์ถูกต้อง
- ประกอบคลิปจาก `edit.json` ไฟล์เดียว: ตัดช็อต ซ้อนกรอบ เกรดสี วางเพลง แล้วปรับความดังแบบสองรอบให้ได้ -14 LUFS
- ตรวจผลงานของตัวเอง: จำนวนเฟรม ความดังที่วัดจากไฟล์จริง และคัตที่วางแผนไว้อยู่ตรงเฟรมที่ตั้งใจหรือไม่
- ทดสอบคลิปใดก็ได้ ทั้งของเราและของคนอื่น ว่าตัดลงจังหวะเพลงไหม แล้วเทียบกับคะแนนที่การตัดแบบสุ่มจะได้

## สิ่งที่ต้องมี

- ffmpeg 8.1.1 และ ffprobe อยู่บน `PATH`
- Python 3.12 พร้อม `numpy`, `scipy` และ `playwright` (ติดตั้ง Chromium แล้ว)
- ฟอนต์ Prompt (ถ้าไม่มี เทมเพลตจะใช้ Leelawadee UI แทน)
- ไม่ต้องใช้ demucs หรือ librosa

เวอร์ชันข้างต้นยืนยันบนเครื่องที่ใช้พัฒนาเมื่อ 8 ตุลาคม 2569

โฟลเดอร์นี้คือสกิลของ Claude Code เมื่อวางไว้ที่ `~/.claude/skills/promotioncut` จะเรียกใช้ได้ด้วย `/promotioncut` ขั้นตอนฉบับเต็มอยู่ใน `SKILL.md` (ภาษาไทย) รวมถึงแผนรายห้องและตัวเลขเป้าหมาย

## เริ่มใช้งาน

เก็บของทุกอย่างของคลิปหนึ่งไว้ในโฟลเดอร์งานเดียว ตั้งชื่อไฟล์เป็น ASCII ข้อความที่จะขึ้นจอให้เขียนลงไฟล์ JSON แบบ UTF-8 ห้ามส่งทาง command line เพราะ Git Bash จะเปลี่ยนตัวอักษรที่ไม่ใช่ ASCII เป็น `?????` แล้วยังจบด้วย exit 0

```bash
SK="<path ของโฟลเดอร์นี้>"
```

1. วัดกริดของเพลง

```bash
python "$SK/scripts/pc_beat.py" grid "<งาน>/music.wav" --fps 25 --out "<งาน>/grid.json"
```

2. วางแผนคลิปเป็นห้อง แผนตั้งต้นใน `SKILL.md` มี 21 ห้อง (84 บีต): การ์ดเปิด บิลด์ โลโก้รัว การ์ดชื่องาน drop A เบรก drop B และการ์ดปิด

3. เลือกช็อตจาก contact sheet แล้วจดวินาทีเริ่มของแต่ละช็อต

```bash
ffmpeg -hide_banner -v error -i "<ฟุตเทจ.mp4>" -vf "fps=2,scale=270:-1,tile=6x4" -q:v 3 "<งาน>/sheets/NAME_%02d.jpg" -y
```

4. เรนเดอร์กรอบและการ์ด เปิดดู PNG ทุกใบก่อนนำไปใช้

```bash
python "$SK/scripts/pc_card.py" "$SK/assets/frame.html" "<งาน>/frame.png" --data "<งาน>/frame.json" --size 1080x1080 --transparent
python "$SK/scripts/pc_card.py" "$SK/assets/card.html" "<งาน>/cards/title.png" --data "<งาน>/title.json" --size 1080x567
```

5. คัดลอก `assets/edit.example.json` ไปไว้ในโฟลเดอร์งานแล้วเติมให้ครบ path ของไฟล์อ้างอิงจากตำแหน่งของ `edit.json`

6. ประกอบคลิป

```bash
python "$SK/scripts/pc_build.py" "<งาน>/edit.json" -o "<งาน>/out.mp4"
```

7. ตรวจผลลัพธ์

```bash
python "$SK/scripts/pc_beat.py" check "<งาน>/out.mp4"
```

## วิธีใช้

| ไฟล์ | หน้าที่ |
|---|---|
| `scripts/pc_beat.py` | `grid`: เทมโป จังหวะที่หนึ่งแรก และตารางห้อง `check`: คัตลงจังหวะไหม เทียบกับการตัดแบบสุ่ม |
| `scripts/pc_card.py` | เรนเดอร์เทมเพลต HTML เป็น PNG ด้วย Chromium |
| `scripts/pc_build.py` | ประกอบคลิปจาก `edit.json` ซ้อนกรอบ เกรดสี วางเพลง ตั้งความดัง แล้วตรวจตัวเอง |
| `assets/frame.html` | กรอบ 1080x1080 มีช่องวิดีโอโปร่งใส 1080x567 ที่ y=264 |
| `assets/card.html` | การ์ดเปิด การ์ดชื่องาน และการ์ดปิด ขนาดเท่าช่องวิดีโอ |
| `assets/edit.example.json` | โครง `edit.json` ตามแผน 21 ห้อง ตั้งใจให้ยังไม่ครบ อ่าน `_note` ในไฟล์ก่อนใช้ |
| `references/digitech-teardown.md` | ผลถอดสูตรคลิปอ้างอิงที่วัดมา (ภาษาไทย) |

คีย์ของเทมเพลต (ไฟล์ JSON ที่ส่งผ่าน `--data`):

| เทมเพลต | คีย์ |
|---|---|
| `frame.html` | `headline1`, `headline2`, `date`, `venue`, `cta`, `logos` (รายการ path), `vars` |
| `card.html` | `kicker`, `title`, `sub`, `logos`, `vars` |

ในข้อความ `*คำ*` คือสีเน้น `\n` คือขึ้นบรรทัดใหม่ และค่าว่างคือซ่อนบล็อกนั้น ส่วน `vars` ใช้แก้ค่า CSS เช่น `bg1`, `bg2` และ `accent`

ฟิลด์หลักของ `edit.json`:

| ฟิลด์ | ความหมาย |
|---|---|
| `grid` | `bpm` กับ `first_downbeat` จากขั้น 1 |
| `music_offset` | วินาทีในไฟล์เพลงที่คลิปเริ่ม |
| `end` | บีตที่คลิปจบ |
| `at` | จุดเริ่มของช็อต นับเป็นบีตจากจังหวะที่หนึ่งแรกของเพลง ใส่ทศนิยมได้ (0.5 คือครึ่งบีต) ช็อตแรกเริ่มที่เฟรม 0 เสมอ |
| `run` + `until` | ชุดภาพนิ่งที่กระจายเท่า ๆ กันจนถึง `until` ใช้ทำโลโก้รัว |
| `fit` | `"cover"` ทำให้ภาพนิ่งเต็มช่อง ค่าปกติคือจัดให้พอดีช่องบนพื้นสี `card_bg` |
| `grade` | `"navy"` คือโทนของคลิปอ้างอิง `"none"` คือไม่เกรด |
| `fx` | เอฟเฟกต์บนเฟรมแรก ๆ ของช็อตที่เข้ามา (ใส่หรือไม่ใส่ก็ได้) |

| `fx` | ผล |
|---|---|
| `flash` | ขาวฟุ้งแล้วจางใน 3 เฟรม |
| `punch` | เข้ามาแบบซูม 30% แล้วคลายใน 6 เฟรม |
| `rgb` | สีเหลื่อมซ้ายขวา 5 เฟรม |
| `blur` | เบลอ 4 เฟรมแล้วชัด |

ผลตัดสินที่ `pc_beat.py check` พิมพ์ออกมา:

| ผลตัดสิน | ความหมาย | ทำอะไรต่อ |
|---|---|---|
| `ON GRID` | คัตลงจังหวะเพลง | ผ่าน |
| `OFF BY A CONSTANT ... ms` | คัตสม่ำเสมอ แต่เลื่อนจากจังหวะเท่ากันทุกจุด | แก้ `first_downbeat` หรือ `music_offset` ไม่ต้องแก้รายการช็อต |
| `PARTLY ON GRID` | บางช่วงลง บางช่วงไม่ลง | หาช็อตที่ใส่ `at` ไม่เป็นบีต |
| `NOT SYNCED` | เท่ากับตัดแบบสุ่ม | เพลงกับกริดไม่ใช่ชุดเดียวกัน กลับไปขั้น 1 |

ตาราง `PACE vs MUSIC` ท้ายผลตรวจแสดงจำนวนคัตต่อวินาทีเทียบกับระดับเสียงเพลง ทีละสองห้อง

## หลักการทำงาน

- **เพลงมาก่อน คัตนับเป็นบีต** `edit.json` เก็บเลขบีต แล้วตัวประกอบแปลงเป็นเฟรมให้ ถ้าเทมโปหารเฟรมลงตัว (100 BPM ที่ 25 fps หรือ 120 BPM ที่ 30 fps ซึ่งได้ 15 เฟรมต่อบีตทั้งคู่) ทุกบีตจะตรงเฟรมพอดี
- **ความถี่ของคัตตามพลังของเพลง** ท่อนดังตัดถี่ ท่อนเบรกปล่อยให้หายใจ
- **เชื่อตัวตรวจ ไม่เชื่อหู และไม่เชื่อ exit code** ระหว่างสร้างสกิลนี้ ffmpeg เคยทิ้งเฟรมไป 112 เฟรมเงียบ ๆ แล้วยังจบด้วย exit 0 สิ่งเดียวที่จับได้คือการวัดไฟล์ผลลัพธ์
- **ทุกท่อนถูกแปลงเป็น BT.709 และติดป้ายสีชุดเดียวกันก่อนนำมาต่อ** เพราะท่อนเดียวที่ติดป้ายต่างจากท่อนอื่นคือต้นเหตุของเฟรมที่หายไปข้างต้น
- **การซ้อนภาพทำใน `rgb24`** บน ffmpeg 8.1.1 การแปลง yuv420p เป็น `gbrp` ทำให้ภาพกว้าง 1080 มี 8 คอลัมน์ขวาสุดเป็นสีดำ
- **ช่องวิดีโอสูง 567 px เป็นเลขคี่ ซึ่ง yuv420p เก็บไม่ได้** จึงเรนเดอร์ท่อนให้สูง 568 แล้วตัดเหลือ 567 ใน RGB
- **หาจังหวะที่หนึ่งด้วย RMS เชิงเส้นทีละบีต** ถ้าวัดเป็น dB เสียง riser ก่อน drop จะชนะ drop เอง
- **คัตในช่วงภาพรัว (ช็อตสั้นกว่า 5 เฟรม) ไม่ถูกนับในการทดสอบจังหวะ** เพราะตั้งใจให้อยู่นอกกริดอยู่แล้ว

## ผลการทดสอบ

วัดเมื่อ 8 ตุลาคม 2569 ความคลาดเคลื่อนที่ยอมให้คือหนึ่งเฟรม

| คลิป | คัตที่ลงจังหวะ | ผลตัดสิน |
|---|---|---|
| คลิปทดสอบที่ประกอบด้วยสกิลนี้ (48 วินาที 87 ช็อต) | 97.2% (ถ้าตัดแบบสุ่มจะได้ 14.0%, z = +20.2) | `ON GRID` |
| คลิปเดียวกัน แต่จงใจเลื่อนกริดไป 143 ms | ถูกจับว่าเลื่อนคงที่ +141 ms | `OFF BY A CONSTANT` |
| คลิปอ้างอิงที่เป็นต้นแบบของสกิล | 10.2% | `NOT SYNCED` |

ความดังของคลิปทดสอบ วัดจากไฟล์จริง: -13.9 LUFS, true peak -1.5 dBTP (เป้าคือ -14 LUFS และ true peak ไม่เกิน -1.5 dBTP)

ทดสอบกับคลิปของตัวเองได้ด้วยคำสั่งนี้

```bash
python "$SK/scripts/pc_beat.py" check "<งาน>/out.mp4"
```

คลิปทดสอบทำจากฟุตเทจสังเคราะห์ และไม่ได้รวมอยู่ใน repo นี้

## ข้อจำกัดที่ทราบ

- ทดสอบมาด้วยฟุตเทจสังเคราะห์เท่านั้น งานแรกที่ใช้ฟุตเทจจริงให้ดู contact sheet ของผลลัพธ์อย่างละเอียด
- ทดสอบแค่อัตราส่วน 1:1 ที่ 25 fps ขนาดและ fps อื่นตั้งได้ผ่าน `size`, `window`, `fps` และ `vars` ของกรอบ แต่ยังไม่เคยทดสอบ
- ยังไม่มีทรานซิชันหนักแบบคลิปอ้างอิง ได้แก่ glitch แถบสี, light leak, split screen และการหมุนพร้อม zoom blur
- ไม่มีซับ ไม่มีเสียงพากย์ ไม่มี SFX
- ต้องเตรียมเพลงที่มีสิทธิ์ใช้มาเอง ห้ามหยิบเพลงจากคลิปของคนอื่น
- คัตระหว่างสองช็อตที่หน้าตาคล้ายกันจะตรวจไม่เจอ ตัวเลข "planned cuts found" จึงอาจขาดไปเล็กน้อยทั้งที่ไม่มีอะไรผิด

## เกี่ยวกับคลิปอ้างอิง

สูตรนี้มาจากการถอดและวัดโฆษณางานอีเวนต์ของบุคคลที่สามซึ่งโพสต์ไว้แบบสาธารณะ โดยวิเคราะห์เพื่อการศึกษา ตัวเลขทั้งหมดอยู่ใน `references/digitech-teardown.md` สกิลนี้เก็บโครงและสัดส่วนของคลิปนั้นไว้ แล้วแก้จุดอ่อนใหญ่ที่สุด คือคลิปอ้างอิงไม่ได้ตัดภาพให้ลงจังหวะเพลง

โปรเจกต์นี้ไม่มีส่วนเกี่ยวข้องกับงานดังกล่าวหรือผู้จัดงาน และไม่มีฟุตเทจ เพลง หรือโลโก้ของงานนั้นอยู่ใน repo
