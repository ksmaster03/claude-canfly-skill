# /promotioncut ตัดคลิปโปรโมตให้ลงจังหวะเพลง

ผลลัพธ์คือคลิป 1:1 ราว 40-50 วินาที: ฟุตเทจตัดเร็วอยู่ในช่องกลางเฟรม ล้อมด้วยกรอบที่มีพาดหัว วันที่ สถานที่ และปุ่ม CTA ค้างตลอดคลิป เสียงเป็นเพลงบรรเลงล้วน

สูตรนี้ถอดจากโฆษณางาน DigiTech ASEAN Thailand & AI Connect 2026 (ตัวเลขเต็มอยู่ใน `references/digitech-teardown.md`) แล้วแก้จุดอ่อนใหญ่ที่สุดของต้นแบบ คือ **ต้นแบบตัดภาพไม่ลงจังหวะเพลงเลย** วัดได้ 12.6% เทียบกับ 14.0% ถ้าตัดแบบสุ่ม

## หลักคิด 3 ข้อ

1. **เพลงมาก่อน คัตนับเป็นบีต ไม่ใช่วินาที** `edit.json` เขียนตำแหน่งคัตเป็นเลขบีต ตัวประกอบจะแปลงเป็นเฟรมให้เอง คัตจึงลงกริดโดยโครงสร้าง ไม่ต้องเล็งด้วยมือ
2. **ความถี่ของคัตตามพลังของเพลง** ท่อนดังตัดถี่ ท่อนเบรกปล่อยให้หายใจ ต้นแบบทำกลับกันในครึ่งหลัง (เพลงดังขึ้น 1.0 dB แต่ตัดช้าลงจาก 2.26 เหลือ 1.41 คัตต่อวิ)
3. **เชื่อตัวตรวจ ไม่เชื่อหู และไม่เชื่อ exit code** ระหว่างสร้างสกิลนี้ ffmpeg เคยทิ้งเฟรม 112 เฟรมเงียบ ๆ แล้วจบด้วย exit 0 สิ่งเดียวที่จับได้คือการวัดผลลัพธ์จริง

## ใช้สกิลไหนเมื่อไร

- อยากรู้ว่าคลิปคนอื่นทำยังไง ให้ไป [[reelcut]] ก่อน แล้วค่อยกลับมาที่นี่ตอนจะสร้าง
- ฟุตเทจคนพูด ต้องตัดตามคำพูดและใส่ซับ ให้ไป [[vdocut]]
- ยังไม่มีเพลง ให้ทำเพลงด้วย [[sunobridge]] ก่อน (ดูคำสั่งที่แนะนำในขั้น 1)
- แค่อยากเช็กว่าคลิปที่มีอยู่ตัดลงจังหวะไหม ข้ามไปขั้น 7 ได้เลย

## 2. ขั้นตอน

### ขั้น 1 วัดกริดของเพลง

```bash
python "$SK/scripts/pc_beat.py" grid "<งาน>/music.wav" --fps 25 --out "<งาน>/grid.json"
```

อ่านผล 4 จุด
- `tempo` กับ `first downbeat` คือค่าที่จะใส่ใน `edit.json`
- `confidence` ของ downbeat ถ้าต่ำกว่า 70% ต้องยืนยันก่อนใช้: เวลาเริ่มของห้องที่มี `<- rise` ควรตรงกับจุดที่ drop ลงจริงในเพลง ถ้าคลาดไป 1-3 บีต ให้บวกหรือลบ `first_downbeat` ทีละ 1 บีตจนตรง หรือให้ผู้ใช้ฟังยืนยัน
- ตารางห้อง: แถวที่มี `<- rise` คือ drop แถว `<- fall` คือเบรกหรือท่อนจบ ใช้วางแผนขั้น 2
- ถ้าขึ้น `weak periodicity` แปลว่าเพลงไม่มีจังหวะคงที่ สูตรนี้ใช้ไม่ได้ ให้เปลี่ยนเพลง

ถ้าสั่งทำเพลงใหม่ ให้ขอเทมโปที่หารเฟรมลงตัว คัตทุกบีตจะตรงเฟรมพอดี: **100 BPM ที่ 25 fps** หรือ **120 BPM ที่ 30 fps** (15 เฟรมต่อบีต) และขอโครง 21 ห้อง: ฮิตเปิด 1 ห้อง บิลด์ 3 ห้อง เงียบแล้ว riser 1 ห้อง drop 7 ห้อง เบรก 1 ห้อง drop 7 ห้อง จบ 1 ห้อง เพลงของต้นแบบมีพลังงาน 80% อยู่ต่ำกว่า 200 Hz ซึ่งลำโพงมือถือแทบไม่ออก ควรขอเบสที่มีเนื้อย่านกลางด้วย (ข้อนี้เป็นความเห็น)

### ขั้น 2 วางแผนเป็นห้อง

แผนตั้งต้น 21 ห้อง = 84 บีต (48.0 วิ ที่ 105 BPM, 50.4 วิ ที่ 100 BPM) ปรับเลขบีตตามตารางห้องของเพลงจริง ให้คัตเข้าเนื้อหาตรงกับ drop พอดี

| ห้อง | บีต | เพลง | ภาพ | ความถี่คัต |
|---|---|---|---|---|
| 1 | 0-4 | ฮิตเปิด | การ์ดโลโก้ | ค้างทั้งห้อง |
| 2-4 | 4-14 | บิลด์ | มอนทาจเปิด ภาพกว้าง คนเยอะ | ทุก 1-2 บีต |
| ปลายห้อง 4 | 14-16 | บิลด์สุด | โลโก้พาร์ตเนอร์รัว | 2-3 เฟรมต่อภาพ (ใช้ `run`) |
| 5 | 16-20 | เงียบแล้ว riser | การ์ดชื่องาน | ค้างทั้งห้อง แล้วตัดออกตรง drop |
| 6-12 | 20-48 | Drop A | เนื้อหาหลัก | ทุก 1 บีต |
| 13 | 48-52 | เบรก | ภาพกว้าง ผู้ชม | ทุก 2 บีต |
| 14-20 | 52-80 | Drop B | เนื้อหาต่อ จบด้วยภาพหมู่ | ทุก 1 บีต แทรกครึ่งบีตตรงจุดพีก |
| 21 | 80-84 | ฮิตจบ | การ์ดปิดพร้อมวันที่และ CTA | ค้างทั้งห้อง |

### ขั้น 3 เลือกช็อต

ทำ contact sheet ของฟุตเทจแต่ละไฟล์แล้ว Read ดู จดวินาทีเริ่มของช็อตที่จะใช้ (`in`)

```bash
ffmpeg -hide_banner -v error -i "<ฟุตเทจ.mp4>" -vf "fps=2,scale=270:-1,tile=6x4" -q:v 3 "<งาน>/sheets/NAME_%02d.jpg" -y
```

- เลือกช็อตที่มีการเคลื่อนไหว และให้ช็อตติดกันต่างกันชัด (คน สลับ สินค้า สลับ ภาพกว้าง)
- หลัง `in` ต้องเหลือฟุตเทจยาวพอสำหรับช็อตนั้น ไม่งั้นตัวประกอบจะไม่ยอมทำ และบอกว่าช็อตไหนสั้นไป
- ถ้าฟุตเทจมีคัตอยู่ข้างใน ให้เลือกช่วงที่ไม่ข้ามคัต ไม่งั้นจะได้คัตนอกจังหวะแถมมา

### ขั้น 4 ทำกรอบและการ์ด

เขียนข้อความลงไฟล์ JSON ด้วย Write tool (UTF-8) ห้ามส่งข้อความไทยทาง command line เพราะ Git Bash จะเปลี่ยนเป็น `?????` โดยไม่ฟ้อง

ข้อความการ์ดเปิดกับพาดหัวในกรอบคือฮุกของคลิปแบบนี้ (ไม่มีเสียงพูด) หยิบแม่แบบจากคลัง `~/.claude/skills/vidcraft/references/hooks-50.md` คลิปโปรโมตเหมาะกับกลุ่มชี้ปัญหาของคนดู (1, 3, 44) และข้อ 40, 49, 50 · ย่อให้อ่านจบในช่วงที่การ์ดค้าง (1 ห้อง) และเสนอผู้ใช้ 3 ตัวเลือก

```bash
python "$SK/scripts/pc_card.py" "$SK/assets/frame.html" "<งาน>/frame.png" --data "<งาน>/frame.json" --size 1080x1080 --transparent
python "$SK/scripts/pc_card.py" "$SK/assets/card.html" "<งาน>/cards/title.png" --data "<งาน>/title.json" --size 1080x567
```

| เทมเพลต | คีย์ใน JSON |
|---|---|
| `frame.html` | `headline1`, `headline2`, `date`, `venue`, `cta`, `logos` (รายการ path), `vars` |
| `card.html` | `kicker`, `title`, `sub`, `logos`, `vars` |

- ในข้อความ `*คำ*` คือสีเน้น `\n` คือขึ้นบรรทัดใหม่ ค่าว่าง `""` คือซ่อนบล็อกนั้น
- `vars` แก้ค่า CSS ได้ เช่น `{"bg1":"#0b0828","bg2":"#3b1466","accent":"#3be8ff"}` กรอบยังรับ `text`, `cta-bg`, `cta-text`, `win-y`, `win-h` (สองตัวหลังต้องมีหน่วย เช่น `"264px"` และต้องตรงกับ `window` ใน `edit.json`)
- **Read ไฟล์ PNG ทุกใบก่อนใช้** ดูว่าข้อความไม่ล้น สระไม่ลอย โลโก้ขึ้นครบ
- ไม่ใส่ emoji ไม่ตั้ง letter-spacing กับข้อความไทย และตัวอักษรเทาต้องผ่าน WCAG AA

### ขั้น 5 เขียน edit.json

คัดลอก `assets/edit.example.json` ไปไว้ในโฟลเดอร์งาน path ของไฟล์อ้างอิงจากตำแหน่งของ `edit.json`

- `grid`: ใส่ `bpm` กับ `first_downbeat` จากขั้น 1 · `music_offset`: วินาทีในไฟล์เพลงที่คลิปเริ่ม · `end`: บีตที่คลิปจบ
- `at` นับบีตจากจังหวะที่หนึ่งแรกของเพลง ใส่ทศนิยมได้ (0.5 คือครึ่งบีต) ช็อตแรกเริ่มที่เฟรม 0 เสมอ
- `run` คือชุดภาพนิ่งที่กระจายเท่า ๆ กันจนถึง `until` ใช้ทำโลโก้รัว
- ภาพนิ่งจะถูกจัดให้พอดีช่องบนพื้นสี `card_bg` ถ้าอยากให้เต็มช่องใส่ `"fit": "cover"`
- `grade`: `"navy"` คือโทนของต้นแบบ (ขาวถูกกดลงอมฟ้า ดำอมน้ำเงิน) `"none"` คือไม่เกรด

| `fx` | ผลบนเฟรมแรก ๆ ของช็อตที่เข้ามา |
|---|---|
| `flash` | ขาวฟุ้งแล้วจางใน 3 เฟรม |
| `punch` | เข้ามาแบบซูม 30% แล้วคลายใน 6 เฟรม |
| `rgb` | สีเหลื่อมซ้ายขวา 5 เฟรม |
| `blur` | เบลอ 4 เฟรมแล้วชัด |

ใช้ `fx` ราว 1 จุดทุก 3-4 วินาที วางตรงจังหวะที่หนึ่งของห้องหรือจุดเปลี่ยนท่อน ที่เหลือเป็น hard cut ต้นแบบก็เป็นอย่างนั้น (hard cut 73%)

### ขั้น 6 ประกอบ

```bash
python "$SK/scripts/pc_build.py" "<งาน>/edit.json" -o "<งาน>/out.mp4"
```

ตัวประกอบพิมพ์ 3 บรรทัดที่ต้องอ่าน
- จำนวนเฟรมที่ได้ ต้องเท่าที่วางแผน
- ความดังที่วัดจากไฟล์จริง เป้าคือ -14 LUFS และ true peak ไม่เกิน -1.5 dBTP
- `planned cuts found on their exact frame: N/M` ถ้าขาดไปไม่กี่จุดมักเป็นคัตระหว่างช็อตที่หน้าตาคล้ายกัน แต่ถ้าขึ้น `the timeline drifted` ห้ามส่งงาน

### ขั้น 7 ตรวจผลลัพธ์

```bash
python "$SK/scripts/pc_beat.py" check "<งาน>/out.mp4"
```

| ผลตัดสิน | ความหมาย | ทำอะไรต่อ |
|---|---|---|
| `ON GRID` | คัตลงจังหวะ | ผ่าน |
| `OFF BY A CONSTANT ... ms` | คัตสม่ำเสมอแต่เลื่อนจากจังหวะเท่ากันทุกจุด | แก้ `first_downbeat` หรือ `music_offset` ไม่ต้องแก้รายการช็อต |
| `PARTLY ON GRID` | บางช่วงลง บางช่วงไม่ลง | ดูว่าช็อตไหนใส่ `at` ไม่เป็นบีต |
| `NOT SYNCED` | เท่ากับตัดแบบสุ่ม | เพลงกับกริดไม่ใช่ชุดเดียวกัน กลับไปขั้น 1 |

ตารางท้ายผล (`PACE vs MUSIC`) ใช้เช็กหลักคิดข้อ 2: ช่วงที่เพลงดังควรมีคัตต่อวินาทีมากกว่าช่วงเบา
จากนั้นทำ contact sheet ของ `out.mp4` แล้ว Read ดูด้วยตา และถ้าต้องการเทียบกับต้นแบบทุกมิติให้รันตัววิเคราะห์ของ [[reelcut]]

ตัวตรวจนี้พิสูจน์แล้วทั้งสามทาง: คลิปที่ประกอบจากสกิลนี้ได้ 97.2% ลงจังหวะ (z = +20.2) · คลิปเดียวกันที่จงใจเลื่อนกริด 143 ms ถูกจับว่า `OFF BY A CONSTANT +141 ms` · คลิปต้นแบบได้ 10.2% (`NOT SYNCED`)

## 3. ตัวเลขเป้าหมาย

| มิติ | ต้นแบบ (วัดได้) | เป้าของเรา |
|---|---|---|
| ความยาว | 47.9 วิ = 21 ห้องพอดี | ตัดให้ลงห้องพอดีเช่นกัน |
| พื้นที่วิดีโอ | 52.5% ของเฟรม | เท่าเดิม |
| จำนวนช็อต | 89 ช็อต มัธยฐาน 0.44 วิ | 70-90 ช็อต |
| ชนิดคัต | hard cut 73% เอฟเฟกต์ 13 จุด | hard cut เป็นหลัก `fx` 12-15 จุด |
| คัตลงจังหวะ | 12.6% (สุ่มได้ 14.0%) | เกิน 90% |

| ความดัง | -14.1 LUFS, TP -1.7 dBTP | -14 LUFS, TP ไม่เกิน -1.5 dBTP |
| เสียง | เพลงล้วน ไม่มีพากย์ ไม่มี SFX | เหมือนเดิม |

## 4. Gotchas ที่จ่ายค่าเรียนไปแล้ว

1. **ท่อนวิดีโอที่ติดป้ายสีต่างกันทำให้ ffmpeg ทิ้งเฟรมเงียบ ๆ** ท่อนเดียวที่ติด `bt470bg` ท่ามกลางท่อนที่ไม่ติดป้าย ทำให้ filter graph ถูกสร้างใหม่กลางทาง หายไป 112 เฟรม การ์ดปิดถูกยืดมาอุด และ exit code ยังเป็น 0 `pc_build.py` จึงแปลงทุกท่อนเป็น BT.709 ป้ายเดียวกันก่อนต่อ ถ้าเขียน ffmpeg เองต้องทำแบบเดียวกัน
2. **อย่าแปลง yuv420p เป็น `gbrp`** บน ffmpeg 8.1.1 ภาพกว้าง 1080 (หาร 16 ไม่ลงตัว) จะได้ 8 คอลัมน์ขวาสุดเป็นสีดำ ใช้ `rgb24` แทน
3. **ช่องวิดีโอสูง 567 px เป็นเลขคี่** yuv420p เก็บไม่ได้ ตัวประกอบจึงทำท่อนให้สูง 568 แล้วตัดเหลือ 567 ตอนซ้อนใน RGB
4. **หาจังหวะที่หนึ่งด้วยระดับเสียงเป็น dB จะพลาด** เพราะ riser ก่อน drop ชนะ drop เอง `pc_beat.py` ใช้ RMS เชิงเส้นทีละบีตแทน
5. **คัตในช่วงภาพรัว (ช็อตสั้นกว่า 5 เฟรม) ไม่ถูกนับในการทดสอบจังหวะ** เพราะตั้งใจให้อยู่นอกกริดอยู่แล้ว
6. **คัตระหว่างสองช็อตที่หน้าตาคล้ายกันตรวจไม่เจอ** ตัวเลข `planned cuts found` จึงอาจขาดเล็กน้อยโดยไม่มีอะไรผิด
7. **ต้นแบบไม่ได้ตัดลงจังหวะ** อย่าลอกเวลาคัตของต้นแบบมาใช้ ให้ลอกแค่โครงและสัดส่วน

## 5. สิ่งที่สกิลนี้ยังไม่ทำ

- ทรานซิชันหนักของต้นแบบ: glitch แถบสี, light leak, split screen 5 ช่อง, หมุนพร้อม zoom blur ถ้าต้องการให้ทำเป็นคลิปสั้นแยกแล้วใส่เป็นช็อตหนึ่งใน `edit.json`
- ซับ เสียงพากย์ และ SFX
- อัตราส่วนอื่นนอกจาก 1:1 และ fps อื่นนอกจาก 25 **ยังไม่เคยทดสอบ** ทำได้โดยแก้ `size`, `window`, `fps` และ `vars` ของกรอบ แต่ต้องรันขั้น 6-7 ยืนยันทุกครั้ง
- ทดสอบมาด้วยฟุตเทจสังเคราะห์เท่านั้น งานแรกที่ใช้ฟุตเทจจริงให้ดู contact sheet ของผลลัพธ์อย่างละเอียด
