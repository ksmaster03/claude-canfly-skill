# /mv-reel — คลิปเพลงแนวตั้ง 9:16

ต่อยอดจาก [[musicvideo]] ซึ่งมีทั้ง remaster, `analyse.py`, คอมโพเนนต์ และ `render.mjs` อยู่แล้ว
สกิลนี้เพิ่มสามเรื่องที่แนวตั้งต้องคิดต่างจากแนวนอน: **หาท่อนฮุก · ออกแบบเลย์เอาต์แนวตั้ง · safe area**

พิสูจน์แล้ว (2026-09-06): ตัดท่อนฮุก 16 บาร์ (29.71 วิ) จากเพลง 4:57 เรนเดอร์ 891 เฟรม

## 1. หาท่อนฮุก

```bash
python <skill>/references/hook.py     # -> src/hook.json + หลักฐาน
```

### กฎสองข้อที่ห้ามพลาด

**วัดจากไฟล์ก่อนมาสเตอร์** — มาสเตอร์ที่ดันถึง -9 LUFS จะเหลือ LRA ราว 2 ซึ่งกดท่อนดังกับท่อนเบา
ให้เท่ากันหมด การค้นหาด้วยพลังงานบนไฟล์นั้นได้ผลลัพธ์เป็นสัญญาณรบกวนล้วน ๆ

**ค้นหลายความยาว อย่าใช้ขนาดเดียว** — หน้าต่าง 87 วินาทีกินพื้นที่ 30% ของเพลง 297 วินาที
วางตรงไหนก็ได้ค่าเฉลี่ยพอ ๆ กัน ต้องค้นตั้งแต่ 16 บาร์ขึ้นไปและให้คะแนน **ค่าต่ำสุดในท่อน**
ด้วย ไม่ใช่แค่ค่าเฉลี่ย ไม่งั้นหน้าต่างจะกลืนช่วง breakdown เข้าไปอย่างมีความสุข

### ตรวจคำตอบด้วยวิธีที่ตัวหาไม่ได้ใช้

คะแนนของตัวตรวจจับ **ไม่ใช่หลักฐาน** ในเซสชันต้นแบบ ตัวแรกตอบมาพร้อมคะแนนที่ดูดี แต่ท่อนนั้น
พลังงานต่ำกว่าค่าเฉลี่ยทั้งเพลง 0.6% และกินช่วงที่เบาที่สุดกลางเพลงเข้าไปด้วย จับได้ตอนเอาไปเทียบกับ
เส้นพลังงานดิบต่อ 10 วินาที ซึ่งเป็นข้อมูลที่ตัวตรวจจับไม่ได้ดู

เกณฑ์ที่ควรผ่าน:
- พลังงานเฉลี่ยของท่อน **สูงกว่าค่าเฉลี่ยทั้งเพลงอย่างน้อย 20%**
- ท่อนครอบบล็อกที่ดังที่สุดของเพลง
- **ความยาวหารด้วยบาร์ลงตัว** (16 หรือ 32 บาร์) ถ้าได้ 13.7 บาร์แปลว่าตัดกลางท่อน

## 2. เลย์เอาต์แนวตั้ง — ห้ามครอปจาก 16:9

ภาพพื้นหลังเป็น 16:9 ครอปเป็น 9:16 คือทิ้งภาพไปสองในสาม ต้องออกแบบใหม่ทั้งเฟรม

โครงที่ใช้ได้ผล — **สามโซนแขวนบนเส้นแนวนอนสองเส้น**:

| ส่วน | เนื้อหา |
|---|---|
| บน ~0-450 | ภาพของฉากอื่น (เช่นฉากเมื่อ 15 วิก่อน) เบลอ + ไล่มืด · ทิกเกอร์ BPM/เลขฉาก/timecode · progress bar · ชื่อเพลง |
| กลาง ~424-1031 | การ์ดภาพหลัก 1080x607 อัตราส่วน 16:9 เดิม มี drop shadow และ hairline ที่สว่างตามเบส |
| ล่าง ~1031-1920 | เวที: เงาสะท้อนของภาพ + ลำโพงยืนบนเส้น + แสงกองบนพื้นตามเบส + สเปกตรัมอนาไลเซอร์ |

**เคล็ดที่ได้ผลจริง**
- **แถบบนใช้ภาพคนละฉากกับตรงกลาง** ทำให้สองโซนตัดคนละจังหวะ ไม่อ่านเป็นแผ่นเดียวกัน
- **เงาสะท้อนต้องเรนเดอร์คอมโพเนนต์ตัวที่สองจริง** ไม่ใช่ clone ด้วย CSS เพราะของที่สะท้อนกำลังขยับ
- **เติมพื้นด้วยแสงที่สว่างขึ้นเมื่อเข้าใกล้กล้อง** (ไม่ใช่จางลง) — พื้นเปียกสะท้อนไฟแบบนั้น และนี่คือ
  สิ่งที่ทำให้พื้นที่ดำอ่านเป็น "พื้น" แทน "งานยังไม่เสร็จ"
- ⚠️ **อย่าวางเส้นแสงบนพื้นถี่และสม่ำเสมอเกินไป** จะอ่านเป็น banding ของการเรนเดอร์ ให้ระยะไม่เท่ากัน
- **การ์ดเปิด/ปิดต้องครอบกล่องให้ไป center บนรูป** ไม่ใช่ center ของเฟรม 1920 ซึ่งมักเป็นจุดที่มีของอยู่แล้ว

## 2.5 ซับในเฟรมแนวตั้ง

ใช้ไฟล์ซับตัวเดียวกับตัว 16:9 ได้ (`src/subtitles.json` จาก [[musicvideo]]) — สร้างด้วย
**forced alignment** (`tools/forced.py`) เท่านั้น ไม่ใช่ ASR แล้วจับคู่ ซึ่งวัดผลแล้วได้แค่ 49-58%
ส่วนเพลงที่ไม่ใช่อังกฤษต้องผ่าน `uroman` ก่อน รายละเอียดอยู่ใน [[musicvideo]]

ในเฟรมแนวตั้งต้องปรับสองอย่าง

**ขนาดตัวอักษร** — เฟรมกว้าง 1080 ไม่ใช่ 1920 ตัวอักษรขนาดเดิมจะล้นขอบ ที่ใช้ได้จริงคือ
**34px** (จาก 46px ของแนวนอน) กับ `widthPct` ราว 0.9 ด้วยค่านี้บรรทัดยาว 42 อักขระจะตัดเป็น
สองบรรทัดเองอย่างสวยงาม ไม่ต้องสร้างไฟล์ซับแยก

**ตำแหน่ง** — วางในแถบระหว่างพื้นเวทีกับยอดอนาไลเซอร์ ในเลย์เอาต์ต้นแบบคือช่วง y 1031–1296
ซึ่งเป็น**จุดที่โล่งและมืดที่สุดของเฟรมอยู่แล้ว** ซับจึงแก้ปัญหาสองอย่างพร้อมกัน: มีเนื้อเพลงให้อ่าน
และเติมช่องว่างที่ทำให้เฟรมดูเหมือนงานค้าง อย่าเอาไปไว้ก้นเฟรม เพราะเป็นเขตที่ UI ของแพลตฟอร์มทับ

**เช็คก่อนว่าท่อนที่ตัดมีคำร้องแค่ไหน** — ท่อนฮุกมักเป็นวรรคสั้นซ้ำ ๆ ในเคสต้นแบบช่วงฮุก 29.7 วิ
มีซับบนจอแค่ 16.0 วิ (54%) ที่เหลือเป็นดนตรีล้วน นั่นถูกต้องแล้ว แต่ต้องรู้ก่อนตัดสินใจ ไม่ใช่
ไปเจอตอนดูคลิปเสร็จ

```python
inside  = [l for l in L if l["start"] >= a and l["end"] <= b]
overlap = [l for l in L if l["end"] > a and l["start"] < b]   # ตัวที่ต้องใช้
```
นับแบบแรกได้ 3 บรรทัด แบบที่สองได้ 4 — บรรทัดที่คร่อมขอบช่วงก็ขึ้นจอเหมือนกัน

**ถ้าต้องแก้คอมโพเนนต์ที่ใช้ร่วมกับตัว 16:9 ระหว่างที่เรนเดอร์ตัวนั้นอยู่** ให้เพิ่มเป็นพารามิเตอร์
ที่มีค่าเริ่มต้นเท่าพฤติกรรมเดิมเป๊ะ แล้ว**พิสูจน์ด้วยการเทียบพิกเซล**กับเฟรมจากก้อนที่เรนเดอร์ไปแล้ว
ค่าต่างระดับ 1–2/255 คือร่องรอยการบีบอัด h264 ไม่ใช่ภาพเปลี่ยน

## 4. เรนเดอร์เฉพาะช่วง

```bash
node tools/render.mjs MvTall hook.mp4 --from=<startFrame> --to=<endFrame>
```
`render.mjs` จะ seek เสียงให้ตรงกับเฟรมแรกอัตโนมัติ คอมโพเนนต์อ่านเฟรมสัมบูรณ์จาก `features.json`
อยู่แล้ว ภาพจึงตรงกับเสียงช่วงนั้นพอดีโดยไม่ต้องแก้อะไร

**ผลข้างเคียงที่ต้องรู้:** การ์ดเปิดและการ์ดปิดผูกกับเวลาสัมบูรณ์ จึงไม่โผล่ในคลิปฮุก
ถ้าอยากได้ชื่อเพลงตอนต้นคลิป ต้องทำการ์ดที่อิงเฟรมเริ่มของช่วงแทน

**ข้อความบนการ์ดเปิดและแคปชันโพสต์** หยิบแม่แบบจากคลัง `~/.claude/skills/vidcraft/references/hooks-50.md` ได้ (กลุ่มอารมณ์และความเร่งด่วน เช่นข้อ 27 เข้ากับคลิปเพลงที่สุด) · "ฮุก" ในคลังหมายถึงประโยคเปิดคลิป คนละเรื่องกับท่อนฮุกของเพลงใน §1
