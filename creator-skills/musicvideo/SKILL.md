# /musicvideo — มิวสิควิดีโอ 16:9 จากเพลงที่มีอยู่

พิสูจน์แล้วกับ "AI HARD, BURN TOKEN HARD" (2026-09-06): เพลง 4:57 → 8,911 เฟรม 1080p
เรนเดอร์บน T14 ราว 25 นาที

**ใช้สกิลนี้เมื่อมีไฟล์เพลงอยู่แล้ว** ถ้ายังต้องแต่งเพลงก่อน ใช้ [[sunobridge]] แล้วค่อยกลับมา

## กติกาข้อเดียวที่สำคัญที่สุด

**วัด อย่าเดา และตรวจคำตอบด้วยวิธีที่ตัวที่ให้คำตอบไม่ได้ใช้**

ทุกความผิดพลาดใหญ่ในเซสชันต้นแบบมาจากการเชื่อค่าที่ยังไม่ได้ตรวจ — BPM ที่ตัวตรวจจับมั่นใจแต่ผิด,
เชน EQ ที่ดูสมเหตุสมผลแต่ทำให้ย่าน air พุ่ง 21 dB, เงาสะท้อนที่ไม่เคยแสดงผลเลยทั้งเรนเดอร์,
สคริปต์ที่รายงาน exit 0 แล้วไม่มีไฟล์ ทั้งหมดถูกจับได้ด้วยการวัดซ้ำเท่านั้น ไม่ใช่ด้วยการอ่านโค้ด

## ลำดับงาน

### 0. เตรียม
```bash
mkdir -p <proj>/{src/components,tools,audio,public/img,out}
cp -r <skill>/template/* <proj>/     # theme/features/components/tools ครบ
cd <proj> && npm install             # remotion 4.0.521 + react 19
```

### 1. Remaster (ทำก่อนเสมอ — MV ต้องใช้ไฟล์เสียงตัวสุดท้าย ไม่งั้นเรนเดอร์ซ้ำ)

ถามผู้ใช้ก่อนว่าเอาโทนไหน แล้ววัดต้นฉบับ:
```bash
ffmpeg -hide_banner -i in.wav -af loudnorm=I=-9:TP=-1:LRA=8:print_format=json -f null -
```

**วิเคราะห์สมดุลความถี่ก่อนตั้ง EQ เสมอ** (ดู `references/analyse-spectrum.py`) เพลงเบสหนักส่วนมาก
เบสล้นอยู่แล้ว การ "ยกเบส" ตามสัญชาตญาณจะทำให้บวมและลิมิตเตอร์กดทั้งเพลงทุกครั้งที่เบสตก
สิ่งที่ทำให้ "แน่น" คือ **บีบย่านต่ำแยก (multiband) + ตัด subsonic + ดึงกลางกลับ**

⚠️ **เชนมาสเตอร์ต้องทำใหม่ทุกเพลง อย่าใช้ซ้ำ** — สองเพลงที่ทำมาสมดุลกลับด้านกันสนิท
เพลงแรกซับสูงกว่าย่านพันช์ 1.9 dB เพลงที่สองต่ำกว่า 3.5 dB ถ้าเอาเชนแรกไปใช้กับเพลงที่สอง
จะกดซับลงอีก 5.5 dB คือฆ่าย่านต่ำทิ้ง

มีเชนตัวอย่างสองแบบ: `references/master-chain.txt` (อิเล็กทรอนิกส์เบสหนัก) และ
`references/chain-rock.txt` (ร็อก สเตอริโอกว้าง) ส่งเข้าเครื่องมือด้วย `--chain`:

```bash
ffmpeg -y -i in.wav -filter_complex_script master-chain.txt -map "[out]" -c:a pcm_s24le tone.wav
ffmpeg -y -i tone.wav -af "volume=<drive>dB,alimiter=limit=0.776:attack=5:release=70:level=disabled" -c:a pcm_s24le master.wav
```
ไล่ `<drive>` ทีละ 0.6 dB จนได้ LUFS ตามเป้า **แล้ววัดซ้ำทุกครั้ง**

### 2. วิเคราะห์เพลง
```bash
python tools/analyse.py     # -> src/features.json
```
ให้ค่า: BPM + เฟสบีต, สเปกตรัม 48 ช่อง, 5 ย่าน, rms, คัตลิสต์ตามพลังงาน — ทั้งหมดรายเฟรม

### 3. ภาพพื้นหลัง
ใช้ `$PROJECTS/chatgpt-bridge` (`chatgpt-batch.mjs` เปิด session เดียวเจนหลายภาพ เร็วกว่าและ
เลี่ยง profile lock) เจน 12 ภาพลง `public/img/` ชื่อ `01-xxx.png` ... `12-xxx.png`

**เคล็ดที่ทำให้ได้ 16:9 จริง** — ต้องขึ้นต้น prompt ด้วย
`Generate a WIDE LANDSCAPE image, 16:9 aspect ratio (1536x1024 pixels), not square.`
ถ้าเขียนแค่ "16:9 widescreen composition" ท้าย prompt GPT-4o มักคืนภาพจัตุรัส

สไตล์ที่ใช้ได้ผล: `cinematic photograph, dark moody studio, deep black background, strong
amber-orange key light with cyan rim light, volumetric haze, shallow depth of field, high
contrast, subtle film grain, photorealistic, NO text, NO logos, no people`

⚠️ **อย่าสั่งให้ "เว้นครึ่งล่างโล่ง"** — จะได้ภาพที่ครึ่งล่างดำสนิท พอเอามาวางในเฟรมจะเกิดแถบดำตาย
ที่ดูเหมือนงานยังไม่เสร็จ สั่งแค่ว่าอย่าให้ของรกกลางเฟรมพอ

```bash
node tools/available.mjs    # เขียน src/available.json = ภาพที่มีจริง
```
ต้องรันก่อนเรนเดอร์ทุกครั้ง — Remotion จะพังถ้า `staticFile()` ชี้ไฟล์ที่ไม่มี

### 4. ประกอบภาพ
แก้ `src/theme.ts` (TITLE, ARTIST, สี) แล้วจัดองค์ประกอบใน `src/MvWide.tsx`

**เรนเดอร์ภาพนิ่งดูก่อนเสมอ อย่างน้อย 4 เฟรมกระจายกัน แล้วเปิดดูด้วยตาจริง**
```bash
node node_modules/@remotion/cli/remotion-cli.js still src/index.ts MvWide out/s.png --frame=4500 --log=error
```
ถ้าจะตรวจรายละเอียดเล็ก ๆ (เช่น เงาสะท้อนมาหรือยัง) ให้ **ครอปแล้วซูม** อย่าดูแต่ภาพเต็ม —
เงาสะท้อนที่ไม่เคยแสดงผลรอดสายตามาได้ทั้งเรนเดอร์เพราะดูแต่ภาพย่อ

### 4.5 ซับเนื้อเพลง

**ขอเนื้อฉบับจริงจากผู้ใช้ก่อน อย่าไปขุดเอง** เจ้าของเพลงวางให้ได้ในไม่กี่วินาที
สองเพลงที่ทำมาเสียเวลาหลายรอบเพราะไปดึงจากหน้าเว็บแล้วให้อัลกอริทึมเดาโครงบรรทัดเอง
⚠️ **เมทาดาทาใน mp3 เชื่อไม่ได้** — Suno เขียนแท็ก `lyrics-eng` มาให้ แต่เพลงที่สองขาดไป 2 ท่อนเต็ม ๆ

**ใช้ forced alignment เท่านั้น** วิธีอื่นวัดผลแล้วไม่พอ:

| วิธี | บรรทัดที่ยึดได้ |
| --- | --- |
| timing จากแพลตฟอร์ม | เพี้ยนกับเสียงร้อง ผู้ใช้จับได้ ไม่มีตัวเลขไหนจับได้ |
| ASR จากมิกซ์เต็ม + จับคู่ | 49% |
| ASR จาก stem เสียงร้อง + จับคู่ | 58% |
| **forced alignment กับเนื้อฉบับจริง** | **100% ทั้งสองเพลง สองภาษา** |

ที่ชนะไม่ใช่เพราะโมเดลดีกว่า แต่เพราะ**โจทย์เล็กกว่า** — ASR ถูกถามว่า "ร้องอะไร" ซึ่งไม่มีใครต้องรู้
เพราะเนื้ออยู่ในมือแล้ว ส่วน forced alignment ถูกถามแค่ว่าคำที่รู้อยู่แล้ววางตรงไหนของคลื่นเสียง

```bash
demucs --two-stems=vocals -n htdemucs -d cpu -o out/stems audio/source.wav
ffmpeg -y -i out/stems/htdemucs/source/vocals.wav \
  -af 'highpass=f=70,loudnorm=I=-16:TP=-1.5:LRA=11' -ar 16000 -ac 1 out/vocals_asr.wav
python tools/forced.py out/vocals_asr.wav src/lyrics_source.txt src/subtitles.json <lang>
```

**ภาษาที่ไม่ใช่อักษรโรมันต้องแปลงก่อน** — พจนานุกรมโมเดลมี 29 ตัวเป็น a-z ภาษาไทยล้มด้วย
`KeyError` ที่อักษรตัวแรก ต้องผ่าน `uroman` ซึ่งเป็นวิธีที่เอกสารโมเดลกำหนดไว้เอง

**ตรวจด้วยวิธีที่ตัวจัดเรียงไม่ได้ใช้** — วัดพลังงานใน stem แล้วดูว่าหน้าต่างของแต่ละบรรทัด
มีเสียงร้องจริงกี่เปอร์เซ็นต์ ได้ 86% (เพลงอังกฤษ) และ 76% (เพลงไทย) **ต่ำกว่า 70% อย่าเรนเดอร์**

**นับบรรทัดเทียบเนื้อฉบับจริงเสมอ** — ตัวจัดเรียงเคยรายงาน "121/121 = 100%" ทั้งที่เนื้อมี 111 บรรทัด
ส่วนต่าง 10 คือหัวข้อท่อนที่กำลังจะขึ้นจอ

**ฟอนต์** — เทมเพลตมาพร้อม Arial Black ซึ่ง**ไม่มีอักษรไทย** เพลงไทยจะได้กล่องสี่เหลี่ยมทั้งเพลง
รัน `tools/embed-fonts.py` ฝัง Sarabun แล้ว mount `<Fonts/>` ในทุกคอมโพสิชัน ไทยต้อง
`line-height` ราว 1.34 และ **`letter-spacing: 0` เสมอ**

รายละเอียดทั้งหมดอยู่ใน `references/subtitles.md`

### 5. เรนเดอร์ + ตรวจ
```bash
node tools/render.mjs MvWide out.mp4              # ทั้งเพลง
node tools/render.mjs MvTall hook.mp4 --from=A --to=B   # เฉพาะช่วง
```
เรนเดอร์เป็นก้อนละ 900 เฟรม แคชไว้ ถ้าล้มก็ทำต่อจากก้อนเดิม ตรวจจำนวนเฟรมทุกก้อน + หลัง concat +
หลัง mux อัตโนมัติ

**ตรวจไฟล์ที่ได้เองอีกชั้น:**
```bash
ffprobe -v error -count_frames -select_streams v:0 -show_entries stream=nb_read_frames -of csv=p=0 out.mp4
ffmpeg -hide_banner -i out.mp4 -af loudnorm=I=-9:TP=-1:LRA=8:print_format=json -f null -
```

MV จากเพลงที่มีอยู่ไม่มีบทพูด ใช้คลังฮุก `~/.claude/skills/vidcraft/references/hooks-50.md` เฉพาะกับข้อความการ์ดเปิด (ถ้ามี) และแคปชันตอนโพสต์ · "ฮุก" ในคลังหมายถึงประโยคเปิดคลิป ไม่ใช่ท่อนฮุกของเพลง

## ค่าที่วัดได้ต้องอยู่ที่เดียว

`src/features.json` คือแหล่งความจริงเดียวของ BPM, เฟส, ความยาว และจำนวนเฟรม
`theme.ts` กับ `render.mjs` ต้อง**อ่านจากไฟล์นั้น ห้ามพิมพ์ตัวเลขซ้ำ**

ตอนย้ายเทมเพลตไปเพลงที่สอง ทั้งสองไฟล์ยังค้างค่าเพลงแรก — ธีมบอก 129.26 BPM และ 297.04 วิ
ขณะที่เพลงจริงคือ 132.62 และ 299.96 ถ้าเรนเดอร์ไปจะได้คลิปสั้นกว่าเพลง 2.9 วินาที และทุกการ
เคลื่อนไหวหลุดบีตสะสมไปเรื่อย ๆ ส่วน `render.mjs` ฝัง 8910 ไว้ ซึ่งตัดท้ายทิ้ง 88 เฟรม

ทั้งสองจุด tsc ผ่านหมด ไม่มีอะไรเตือน

## กับดักที่เสียเวลามาแล้ว

| อาการ | ต้นเหตุ |
|---|---|
| ย่าน air พุ่ง +21 dB, filter เตือน "clipping" ทั้งที่ไม่ได้ใส่เกน | `highpass/lowpass/treble` ใส่ `t=h` แต่ไม่ใส่ `w` → ffmpeg อ่านความกว้างเป็น **0.7 Hz** กลายเป็นเรโซเนเตอร์ ตัด `t` ทิ้งใช้ค่า Butterworth |
| ตรวจจับ BPM ได้ค่าขัดกันไปมา score ต่ำ | วัดจากไฟล์**มาสเตอร์** ที่ LRA ถูกกดเหลือ ~2 ทรานเชียนต์หายไป → **ตรวจจับจากไฟล์ก่อนมาสเตอร์ ขับภาพด้วยไฟล์มาสเตอร์** |
| BPM คลาด 1 หน่วยแต่ท้ายเพลงหลุดบีตเป็นวินาที | ค้นด้วยหน้าต่างสั้น → ค้นแบบ comb เต็มความยาวเพลง เบสไลน์ยาวให้ความละเอียดสูง |
| แถบสเปกตรัมย่านแหลมสูงกว่าเบสทั้งที่เพลงเบสหนัก | `sum()` พลังงานในช่อง log — ช่องแหลมกว้าง 1000 Hz ช่องเบสกว้าง 3 Hz → ใช้ `mean()` (ความหนาแน่น) |
| สเปกตรัมเป็น NaN ทั้งอาเรย์ | ช่อง log ล่างสุดแคบกว่าความละเอียด FFT (SR/NFFT) จึงไม่มีค่าอยู่ในช่อง → `mean()` ของอาเรย์ว่าง ให้ fallback ไปช่อง FFT ที่ใกล้ที่สุด |
| แถบสเปกตรัมกระโดดเป็นบล็อกใหญ่ ดูเหมือนหน้าจอโหลด | ใช้แค่ 5 ย่าน → ต้อง 32–48 ช่อง log |
| เงาสะท้อนไม่ขึ้นเลย แต่ภาพยังดูปกติ | `scaleY(-1)` + `transformOrigin:'top'` พลิกขึ้น**บน**ทับตัวเอง ใช้ origin กลาง (ค่าเริ่มต้น) และ **mask ต้องเขียนกลับหัว** (`0deg`) เพราะ mask พลิกตามไปด้วย |
| ภาพนิ่งมีแถบดำตายกลางล่างเฟรม | ม่านไล่มืดสูงเกิน + ภาพต้นทางครึ่งล่างมืด → ลดม่าน เติมเงาสะท้อน ขยับของลงมาใกล้พื้น |
| เส้น 1px ลากขวางภาพดูเป็นเส้นแบ่ง UI | อย่าวาดเส้นพื้นทับรูปถ่าย ให้เงาสะท้อนทำหน้าที่ยึดพื้นแทน |
| วิดีโอได้ 8,895 เฟรมจาก 8,911 | `-shortest` ตัดตาม padding ของ AAC → เอาออก ภาพกับเสียงต่างกันหลักมิลลิวินาทีอยู่แล้ว |
| สคริปต์รายงาน exit 0 แต่ไม่มีไฟล์ | ต่อท่อผ่าน `tail` ทำให้ได้ exit code ของ tail ไม่ใช่ของคำสั่งจริง → **อย่าต่อท่อคำสั่งที่ต้องรู้ผลสำเร็จ** |
| ก้อนที่เขียนค้างถูกใช้เป็นแคช | เช็คแคชด้วยขนาดไฟล์ → เช็คด้วย **จำนวนเฟรม** |
| เขียน .mjs ด้วย heredoc แล้วไฟล์ parse ไม่ผ่าน | `\` และ `\n` ถูกเขียนใหม่ระหว่างทาง → สร้างอักขระพิเศษด้วย `String.fromCharCode()` และรัน `node --check` หลังแก้ไฟล์ .mjs ทุกครั้ง |
| เรนเดอร์ยาวตายราวเฟรม 1,250 | เบราว์เซอร์สะสมหน่วยความจำ → เรนเดอร์เป็นก้อน ก้อนละ ~900 เฟรม |
| เพลงไทยเรนเดอร์เป็นกล่องสี่เหลี่ยมทั้งจอ | ฟอนต์ในเทมเพลตไม่มีอักษรไทย → `embed-fonts.py` แล้ว mount `<Fonts/>` |
| forced alignment ล้มด้วย `KeyError` ที่อักษรตัวแรก | พจนานุกรมโมเดลมี 29 ตัวเป็น a-z → ผ่าน `uroman` ก่อน |
| หัวข้อท่อนขึ้นจอเป็นเนื้อเพลง | ตัวกรองจับแค่ `**[Chorus]**` แต่ Suno เขียน `[Chorus]` → ปอก `*` ออกก่อนเทียบ |

| กราฟิกที่สวยบนภาพถ่ายกลายเป็นสติกเกอร์บนภาพการ์ตูน | ชั้นกราฟิกต้องเข้ากับสไตล์ภาพ และ**อย่าวางของที่ภาพมีอยู่แล้ว** |
