# โมชันกราฟิกแนวตั้ง + เสียงประกอบ (รีลตัวหนังสือ ไม่ใช่ฉากต่อสู้)

ใช้กับรีล 1080x1920 ที่เล่าเรื่องด้วยตัวหนังสือและรูปทรง เช่น Meta One, Claude vs OpenAI, ก.ล.ต.
ตัวเลขในไฟล์นี้มี 2 ที่มา แยกกันชัดเจน:
- **[วัด]** = วัดจากคลิปต้นแบบ 26.5 วิ ของ Pan Kulkeerati (รีลโชว์งานโมชัน, 30fps, 1 ต.ค. 2026) ด้วย `scripts/refstudy.py` และการไล่ดูทีละเฟรม
- **[ค้น]** = จากงานค้นคว้า ดูหัวข้อท้ายไฟล์ ยังไม่ได้ทดลองกับงานเราเอง

คลิปใหม่ที่ผู้ใช้ส่งมาให้ศึกษา: รัน `python scripts/refstudy.py <ไฟล์หรือ URL> <โฟลเดอร์>` ก่อน แล้วค่อยเปิดดูภาพ

## 1. โครงเวลา [วัด]

- **ตัดภาพถี่:** 28 จุดตัดใน 26.5 วิ · ช็อตกลาง 0.80 วิ · สั้นสุด 0.20 วิ · ยาวสุด 2.9 วิ (ฉากปิดท่อน)
  รีลเก่าของเราฉากละ 5–8 วิ ช้ากว่าราว 6–8 เท่า
- **ทุกอย่างอยู่บนตาราง 0.5 วิ (120 BPM):** ช็อตยาว 0.25 / 0.5 / 0.75 / 1.0 / 1.5 วิ ไม่มีค่าแปลก
- **1 ช็อต = 1 คำ หรือ 1 ไอเดีย** ("EVERY" → "เฟรม." → "ทุก" → "CUT." → "ON" → "BEAT.") ไม่ใส่ประโยคยาว
- **เปลี่ยนสีพื้นทุกช็อต** ใช้สีแบน 5 สี วนไป ไม่ใช้ไล่สี: ดำ `#0D0D0F` · ส้ม `#EC5429` · ครีม `#F1EDE4` · น้ำเงิน `#2440EE` · เขียวมะนาว `#D4F53C`
  ตัวหนังสือใช้สีดำหรือครีมเท่านั้น สีส้มไว้เน้นคำเดียว
- **โครง 3 ท่อน:** (ก) โชว์ของทีละอย่าง 0–10 วิ → (ข) ทวนทุกช็อตแบบรัว 0.25 วิ/ช็อต 5 ช็อต → จอดำเงียบ 0.4 วิ → โลโก้ลงพร้อมเสียงหนัก → (ค) ท่อนพูดกับคนดู ช็อตยาวขึ้น 1.1–1.6 วิ จบด้วยชวนทำ (CTA)
- **ตารางรวมช็อต (collage):** ก่อนเข้าท่อน (ค) เอาทุกฉากที่ผ่านมาย่อลงเป็นตาราง 3x3 ให้เห็นพร้อมกัน แล้วซ้อนข้อความทับ

## 2. การเคลื่อนไหวของตัวหนังสือ [วัด]

| สิ่งที่เกิด | ตัวเลข | หมายเหตุ |
|---|---|---|
| คำเด้งขึ้น (ขยายจากเล็ก) | ถึงจุดเกิน **+9%** ใน 0.10 วิ (3 เฟรมที่ 30fps) แล้วนิ่งใน 0.20–0.23 วิ | สัดส่วนสูง 0.75 → 0.96 → 1.09 → 1.00 |
| ระยะห่างระหว่างคำ | **0.10–0.13 วิ ต่อคำ** | เด้งทีละ "คำ/พยางค์" ไม่ใช่ทีละตัวอักษร · คำถัดไปเกิดเป็นตัวเล็กที่มุมขวาล่างของคำก่อน |
| ป้ายใหญ่เลื่อนเข้า | เหลือระยะครึ่งหนึ่งทุกเฟรม ตาเห็นว่าถึงที่ใน 0.2 วิ | 322 → 146 → 66 → 30 → 13 → 5 px · ตรงกับ `ML.expoOut` ยาว 0.3 วิ |
| ค้างให้อ่าน | 0.5–0.55 วิ สำหรับคำเดียว | |
| ป้ายใหญ่เลื่อนออก | เร่งขึ้นเรื่อยๆ (easeInExpo) 0.2 วิ ออกทางเดียวกับที่เข้า | ออก **ก่อน** จุดตัด ไม่ใช่ตัดทิ้งกลางจอ |
| เฟรมสีล้วน | 1 เฟรมแรกหลังจุดตัดเป็นสีพื้นเปล่า แล้วของค่อยเข้า | ทำให้จุดตัดคม |
| ภาพเบลอตามทิศ | ซ้อนสำเนาจางๆ หลายชั้นตามทิศที่เลื่อน เฉพาะ 2–3 เฟรมที่เร็วสุด | |
| คำสำคัญ zoom ลงมา | เริ่มใหญ่ล้นจอ ย่อลงขนาดจริงใน 0.13 วิ + เศษกระดาษกระจาย | ใช้กับจุดลงหนักเท่านั้น (ทั้งคลิปมี 2 ครั้ง) |

- **ทุกช็อตมีของขยับตลอด** แม้ตอนค้างให้อ่าน: เส้นขีดเส้นใต้ลากออก, สวิตช์เลื่อน, เคอร์เซอร์กะพริบ, พื้นหลังข้อความวิ่งเฉียง, ลายกระเบื้องสลับสี
- **ลูกเล่นต่อคำไม่ซ้ำกัน:** เส้นขอบแล้วค่อยเติมสี · ตัดคำด้วยเส้นเฉียง · แยกสี RGB · เรืองแสง · คลื่นเสียงทะลุคำ · ตัวหนังสือเป็นหน้าต่างเห็นลายข้างหลัง
- ฟอนต์อังกฤษ: ตัวแคบหนาตัวพิมพ์ใหญ่ (แนว Bebas/Anton) · ไทย: ตัวหนาเหลี่ยม · คำไทยกับอังกฤษวางคู่กันเป็นคำแปล ("MOTION / เคลื่อนไหว")
  ⚠ ตัวอังกฤษใส่ letter-spacing ได้ **ข้อความไทยห้ามใส่**

## 3. เสียงประกอบ [วัด]

คลิปต้นแบบ **ไม่มีเพลง** เสียงทั้งหมดเป็นเสียงประกอบที่วางตามจังหวะ 120 BPM ฟังเป็นเพลงได้เอง

- **ตัดภาพ 23 จาก 28 จุดมีหัวเสียงภายใน ±70 ms** ค่ากลางห่างกัน +1 ms → วางหัวเสียงบนเฟรมที่ตัดพอดี ไม่ต้องนำ ไม่ต้องตาม
- **เสียงหนาแน่น 3.2 ครั้ง/วิ** (86 หัวเสียง) และ 61 จาก 86 ไม่ได้อยู่ที่จุดตัด = เสียงรับการขยับในช็อต (คำเด้งทีละคำได้ติ๊กทีละครั้ง, สวิตช์, ตัวพิมพ์)
- **เสียงสั้นและมีช่องเงียบ:** เสียงรับจุดตัดยาวไม่เกิน ~0.32 วิ แล้วเงียบสนิท 0.12–0.18 วิ ก่อนเสียงถัดไป ไม่มีหางยาวทับกัน
- **หัวเสียงรับจุดตัด:** ซับไหลลง (ราว 150 → 45 Hz) + คลิกสั้น ไม่ใช่เสียงกลองจริง
- **riser → เงียบ → ลงหนัก** (ใช้ 2 ครั้ง ที่ 47% และ 77% ของคลิป):
  - ครั้งใหญ่: โทนไต่ 310 → 2,900 Hz (3 อ็อกเทฟ) แบบ exp นาน **2.1 วิ** → **เงียบ 0.4 วิ** (ภาพจอดำ) → เสียงลงหนัก ซับยาว 1.5 วิ
  - ครั้งเล็ก: ไต่ 0.95 วิ → เงียบ 0.15 วิ → ลงหนัก
  - ระหว่าง riser ภาพตัดรัวทุก 0.25 วิ
- **ความต่างของระดับเสียง:** ช่วงปกติ -24 dB · จุดลงหนัก -5 dB ห่างกัน **19 dB** (LRA 11 LU) เสียงเบาส่วนใหญ่ทำให้จุดลงหนักรู้สึกหนักจริง
- เสียง UI โทนบริสุทธิ์ (700–1,300 Hz) ใช้กับฉากตัวพิมพ์และการ์ดปิดท้าย
- ⚠ **อย่าลอกระดับ peak:** ต้นแบบ peak +0.3 dBFS (ทะลุเพดาน) · ของเรายังคุม -14 LUFS และ true peak ≤ -1.5 dBTP

### วิธีทำในงานเรา
- `scripts/sfxsynth.py` สังเคราะห์ได้ 9 เสียง: `kick tick pop blip whoosh riser boom glitch shimmer` และวางตามไฟล์ events
  รูปร่างในสเปกโตรแกรมตรงกับต้นแบบแล้ว (ตรวจ 1 ต.ค. 2026) **แต่ยังไม่ได้ให้ผู้ใช้ฟังและอนุมัติ** ทำคลิปทดสอบให้ฟังก่อนใช้ทั้งเรื่อง
- ให้ไฟล์ฉากประกาศ `window.SFX=[{t,k,...}]` จากตารางเวลาเดียวกับที่ใช้วาด เพื่อให้เสียงกับภาพมาจากตัวเลขชุดเดียวกัน
- ถ้ามีเพลงด้วย: ลดเพลง -6 dB ใต้ boom และตัดเพลงให้เงียบจริงในช่องว่างก่อนลงหนัก (เพลงค้างอยู่ = ช่องว่างไม่ทำงาน)
- ฉากต่อสู้ยังใช้ sample จริง (Kenney) ตาม `motion-rules.md` เสียงสังเคราะห์ล้วนใช้กับงานตัวหนังสือ/UI เท่านั้น

### ฟังก์ชันพร้อมใช้: `scripts/motionlib.js` (ทดสอบตัวเลขแล้ว 1 ต.ค. 2026)
- `ML.pop(t)` สปริงของคำเด้ง: ได้ 0.48 → 0.97 → 1.09 → 1.05 → 1.00 ต่อเฟรมที่ 30fps (ต้นแบบวัดได้ 0.75 → 0.96 → 1.09)
- `ML.springFrom(เกิน, เวลาถึงจุดสูงสุด)` ตั้งสปริงจากสิ่งที่ตาเห็น แทนการเดา stiffness/damping
- `ML.backOut(u, s)` · `ML.expoOut` · `ML.expoIn` · `ML.steps(t, 12)` · `ML.stagger(i, n, {each|amount, from, jitter})` · `ML.life(t, t0, t1)` · `ML.shutter(t)`
- แบ่งคำไทย: `Intl.Segmenter('th', {granularity:'word'})` **แบ่งผิดได้** (ทดสอบแล้ว "โปรแกรม" ออกมาเป็น โปร|แก|รม และ "ว่าที่" ติดกัน) → ส่งคำเป็น array ที่แบ่งเองเสมอ ส่วนการแบ่งกลุ่มอักษร (grapheme) ยังใช้ Segmenter ได้

## 4. รายการตรวจก่อนเรนเดอร์รีลตัวหนังสือ

1. ช็อตกลางยาวไม่เกิน 1.5 วิ ในท่อนโชว์ และไม่เกิน 3 วิ ในท่อนอธิบาย (ถ้าข้อความยาว ให้แบ่งเป็นหลายช็อต ไม่ใช่ค้างนานขึ้น)
2. ทุกจุดตัดอยู่บนตารางบีต และมีหัวเสียงบนเฟรมเดียวกัน
3. ของออกจากจอก่อนตัด (0.2 วิ) ไม่หายวับ
4. สีพื้นช็อตติดกันไม่ซ้ำ
5. มีช่องเงียบก่อนจุดลงหนักทุกครั้ง และจุดลงหนักไม่เกิน 2–3 ครั้งต่อคลิป
6. ข้อความไทยยังต้องอ่านทัน: 17 ตัว/วิ ขั้นต่ำ 0.83 วิ (กฎเดิมใน `motion-rules.md`) **ตัดถี่ได้เฉพาะช็อตคำเดียว** ข้อมูลจริงที่คนต้องอ่าน (ตัวเลข วันที่ ชื่อหน่วยงาน) ต้องค้างตามกฎนี้
7. แฟลช/จอสีล้วน: ไม่เกิน 3 ครั้งต่อวินาที (กันคนไวแสง)

## 5. จากงานค้นคว้า [ค้น] (1 ต.ค. 2026 · ยังไม่ได้ลองกับงานเรา ยกเว้นข้อที่เขียนว่าทดสอบแล้ว)

ที่มาของตัวเลขส่วนใหญ่เป็นบล็อกของผู้ผลิตเครื่องมือและครีเอเตอร์ ไม่ใช่งานวิจัย ใช้เป็นค่าตั้งต้นแล้วทำคลิปทดสอบให้ผู้ใช้ดู

### สปริงและ easing ที่โครงการอื่นใช้
| ที่มา | เกินขนาดจริง |
|---|---|
| Remotion / anime.js / Motion ค่าตั้งต้น (mass 1, stiffness 100, damping 10) | 16.3% ถึงจุดสูงสุดที่ 0.36 วิ (ทดสอบด้วย `ML.spring(t,0.5,10)` ได้ 1.163 ตรงกัน) ช้าเกินไปสำหรับรีล |
| สปริงแนว "snappy" (mass 0.4, stiffness 300, damping 14) | 7.4% ถึงจุดสูงสุดราว 0.15 วิ |
| Motion Canvas "Strike" | 10.6% ที่ 0.15 วิ เหมาะกับคำกระแทกและท่าโดนตี |
| GSAP `back.out(s)` ที่ s 1.0 / 1.70158 / 2.5 | 3.7% / 10% / 18.9% (ทดสอบ `ML.backOut` แล้วตรง) |
| Material 3: เข้า `cubic-bezier(0.05, 0.7, 0.1, 1)` ออก `(0.3, 0, 0.8, 0.15)` | ช่วงเวลา 50–200 ms สั้น, 250–400 กลาง, 450–600 ยาว |

- ค่าที่ต้นแบบใช้ (เกิน 9% ที่ 0.10 วิ) เร็วกว่าค่าตั้งต้นของทุกไลบรารี → อย่าใช้ค่าตั้งต้นของ Remotion ตรงๆ
- stagger: GSAP มี `amount` (เวลารวมทั้งบรรทัด) ทำให้บรรทัดยาวสั้นเผยเสร็จพร้อมกัน · Manim ใช้ `lag_ratio = min(4/จำนวนตัว, 0.2)` · anime.js มี jitter แบบมี seed
- เข้าใช้ ease-out ออกใช้ ease-in ไม่ใช้เส้นตรง · ตัวอักษรห่างกัน 2–4 เฟรม (30fps) สำหรับชื่อสั้น, 1–2 เฟรมสำหรับวลียาว, ระดับคำ 6 เฟรม
- เบลอตามการเคลื่อนไหว (แนว Remotion `CameraMotionBlur`): วาดซ้ำ N ครั้งในช่วง ชัตเตอร์/360 ของเฟรมแล้วเฉลี่ย ค่าตั้งต้น 180° 10 ครั้ง
  ที่ 60fps 180° เบลอแค่ 8 ms จึงใช้ 270–360° หรือเปิดเฉพาะเฟรมเร็ว · ซ้อนด้วย `globalAlpha=1/N` บน canvas 8 บิตจะเป็นแถบ ให้เฉลี่ยใน Float32Array หรือเรนเดอร์ N เท่าแล้วให้ ffmpeg `tmix` เฉลี่ย (เวลาเรนเดอร์คูณ N)
- whip pan: เบลอ 5 เฟรมก่อนและหลังจุดตัด พีคบนเฟรมตัด เสียง whoosh พีคตรงกัน
- Remotion ไม่ใช่โอเพนซอร์สเต็มตัว (บริษัทเกิน 3 คนต้องซื้อสิทธิ์) · GSAP ใช้ฟรีแต่ไม่ใช่โอเพนซอร์ส → เขียนสูตรเอง ไม่คัดลอกโค้ด

### เสียง
- whoosh: จุดดังสุดอยู่บนเฟรมตัดหรือช่วงที่ของเร็วสุด ไม่ใช่ต้นไฟล์ · เริ่มก่อนภาพ 10–20 ms · ยาวเท่าการเคลื่อนไหว (ขยับครึ่งวิ ใช้ 0.4–0.5 วิ) · high-pass 80–100 Hz
- riser: จบพอดีจังหวะลง เว้นเงียบสั้นๆ ก่อนเสียงหนัก (ตรงกับที่วัดจากต้นแบบ)
- เสียงหนัก = 3 ชั้นวางตรงกัน: หัวเสียง (เกิน 3 kHz) + เนื้อ (200–500 Hz) + ซับ (40–80 Hz) · ลำโพงมือถือแทบไม่ออกเสียงต่ำกว่า 150 Hz → ต้องมีชั้นเนื้อหรือ `tanh` ให้เกิดฮาร์มอนิก (`sfxsynth.py` ทำแล้วใน `kick` และ `boom`)
- ระดับ: เสียงประกอบเบากว่าเพลง 3–6 dB · fade ท้าย 10–20 ms กันเสียงคลิก · ลดเพลงใต้เสียงพูด 12–18 dB (attack 10–30 ms, release 200–500 ms)

### เครื่องมือสังเคราะห์เสียงจากโค้ด (ยังไม่ได้ติดตั้งหรือลอง)
- jsfxr (Unlicense) และ ZzFX (MIT): เสียง UI/เกมจากชุดตัวเลข ทำงานในหน้า Playwright เดิมได้ · ZzFX ต้องตั้ง `randomness = 0` ให้ผลซ้ำได้
- Tone.js `Tone.Offline` (MIT): เรนเดอร์เสียงออฟไลน์ในเบราว์เซอร์
- pedalboard และ DawDreamer (GPL-3.0): รีเวิร์บ/ฟิลเตอร์บน numpy ใช้เป็นเครื่องมือได้ แต่อย่า import ลงสกิลที่จะแจก
- pyloudnorm (MIT): วัด LUFS ใน numpy
