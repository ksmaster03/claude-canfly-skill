# กับดักที่เจอจริงในงาน MODEL WARS (28-29/09/2026)

## ภาพ
- **กระตุกเพราะปัดตำแหน่งเข้าช่อง:** ตารางพิกเซลอยู่กับที่แต่ไทม์ไลน์เลื่อน → แท่งกระโดดทีละ 24 px ประมาณ 12 ครั้ง/วิ · แก้โดยให้ทั้งตารางเลื่อนตามพิกัดโลกแบบละเอียดกว่าพิกเซล + 60 fps · วัดยืนยันด้วย cross-correlation ของแถบภาพ (ได้ 5 px ทุกเฟรม)
- **วาดความละเอียดต่ำแล้วขยาย = ภาพแตก** ผู้ใช้ไม่ชอบ · ใช้เวกเตอร์ความละเอียดเต็ม (ctx transform scale) แทน
- **`g.filter` ใส่ทุกเส้นที่วาดช้ามาก** · วาดตัวละครที่ต้องซีด/เงาดำลง offscreen canvas แล้ว `drawImage` ครั้งเดียวพร้อม filter → เร็วขึ้นราว 2 เท่า
- `createRadialGradient` พังเมื่อรัศมีติดลบหรือ NaN: ออร่าชาร์จ `2+8*(1+u/A)` ติดลบเมื่อ u < -A → ใส่เงื่อนไข `u>-A` · field ที่ไม่มีอยู่จริง (`L.lv` แทน `e.lv`) ให้ NaN เงียบๆ จนพังที่ gradient
- ดู stack จริงด้วย `pg.evaluate("t=>{try{draw(t);return 'ok'}catch(e){return e.stack}}", t)` · ใส่ `pg.on("pageerror")` ใน render.py
- ท่าที่ใช้ร่วมไฟล์: ตรวจว่าทุกชื่อท่ามีจริง (`P.fire` หายทำ `lean` undefined)
- ข้อความยาวล้นจอ: วัด `measureText` แล้วย่อขนาดให้ไม่เกิน ~700 px
- ป้ายกับ UI ชนกัน (เรดาร์, กราฟ, การ์ด NEW CHALLENGER ที่ออกวันใกล้กัน) · การ์ดที่ซ้อนเวลาให้เลื่อนลงตามลำดับ

## เรนเดอร์
- ความเร็วจริง: screenshot → JPEG → ffmpeg ได้ราว 2–5 เฟรม/วิ ต่อโปรเซส · 3 นาที 60fps ใช้ 4 โปรเซสขนาน 25–40 นาที
- แบ่งก้อนที่จุดตัดฉากเท่านั้น เพราะกล้องแบบ smoothing มี state (ก้อนใหม่จะ snap กล้อง) · ฉากที่กล้องตัดแข็งแบ่งตรงไหนก็ได้
- concat demuxer `-c copy` ได้ถ้าทุกก้อน encode ด้วยพารามิเตอร์เดียวกัน · ตรวจ `pts_time` ที่รอยต่อต้องห่าง 1/60 เท่ากัน
- **scratchpad ถูกล้างระหว่างเซสชัน** (โฟลเดอร์ kenney หายจริง) → ย้ายซอร์สไป `$PROJECTS/<ชื่อ>` + git ตั้งแต่เริ่ม
- ffmpeg `drawtext` ห้ามใช้กับข้อความไทย (สระลอย) · ป้ายภาษาอังกฤษใช้ได้ · ข้อความไทยวาดใน Chromium

## เพลง / Suno (หน้าเว็บเปลี่ยน ก.ย. 2026)
- `cdn1.suno.ai` ตอบ 403 และ fetch ในเบราว์เซอร์ติด CORS → ตัวเช็ก ready เดิมค้างจนหมดเวลา · ตอนนี้โหลดผ่านเมนู Download ด้วย `get-mp3.mjs`
- ปุ่มเมนูชื่อ `More options` · ปุ่มยืนยัน `Unlock & Download` **กินโควตาดาวน์โหลด** (แพ็ก Pro มีจำกัด) · MP3 ถูกติ๊กไว้เป็นค่าเริ่มต้น
- Playwright ของ suno-bridge ต้อง `npx playwright install chromium` เมื่อเวอร์ชันเปลี่ยน
- เพลงจาก Suno ถูกบีบไดนามิก RMS แบน → หาขอบท่อนด้วย timbre novelty ไม่ใช่ RMS · เส้นแนวตั้งในสเปกโตรแกรมมักเป็นแค่ฉาบหาย ไม่ใช่ช่วงเงียบ
- Git Bash ส่งชื่อไฟล์ไทยให้ python ได้ แต่ข้อความไทยใน argument อื่นอาจเพี้ยน → เขียนไฟล์ด้วย `io.open(..., encoding='utf-8')`

## เสียง
- **เพลงร็อคหนาแน่น (dynamic range แคบ) + loudnorm แบบ one-pass → peak เกิน 0 dBFS หลัง encode AAC** (เจอ +0.9 dBFS) · ใส่ alimiter หลัง loudnorm ไม่ช่วย และ linear 2-pass ไปไม่ถึง -14 · ทางที่ได้ผล: `loudnorm=I=-14:TP=-5` (dynamic) ได้ -14.2 LUFS / -2.2 dBTP · วัดด้วย ebur128 ทุกครั้ง
- Suno เพลง rap-rock ตัววัด BPM จับจังหวะขัด (syncopation) ได้ 143.6 ทั้งที่จริง 105.5 · ดู autocorrelation ของเบส: ถ้ามี peak ที่ 4×beat (ความยาวห้อง) ให้เชื่อค่านั้น และเทียบกับ BPM ที่สั่งใน style
- **ทำไม `secana.py` ได้ 143.6:** ใช้ sr 22050 กับ hop 512 ทำให้ BPM ออกได้แค่ค่าเป็นขั้น `60*22050/(512*lag)` → lag 18 = 143.55, lag 24 = 107.67, lag 25 = 103.36 · ค่า 105.5 ออกไม่ได้เลย และ 143.6 กับ 105.5 ต่างกัน 4:3 (จังหวะขัด) ไม่ใช่ครึ่ง/สองเท่า → **BPM จาก secana เป็นค่าประมาณ ต้องหาค่าละเอียดจากการไล่ตารางบีตกับพลังงานเบสเสมอ**
- ลองให้คะแนนตัวเลือก (T, 4T/3, 3T/4, 3T/2, 2T/3) ด้วยค่าเฉลี่ย onset บนตารางบีตแล้ว (1 ต.ค. 2026) **แยกไม่ออก:** เพลงร็อค 105.5 ได้ 140.3 / 91.9 / 105.2 คะแนนเท่ากัน, เพลง 136 เลือก 91.8, เพลง 120 เลือก 60 → ยังต้องเทียบกับ BPM ที่สั่งใน style ของ Suno และดูพีคที่ 4×beat · ทางที่น่าลองต่อคือ Beat This! (ดู `motion-graphics.md`)
- loudnorm แบบ one-pass อาจได้ -12.3 แทน -14 → วัดด้วย `ebur128=peak=true` แล้วปรับ `volume` ซ้ำ
- เสียงสังเคราะห์ numpy ล้วนฟังดูถูก → ใช้ sample จริงเป็นหัวเสียงเสมอ
