# /panya-sync รับส่งความจำและสกิลกับ panya

สคริปต์เดียว ไม่มี dependency รันด้วย node 18 ขึ้นไป:

```
node ~/.claude/skills/panya-sync/scripts/panya-sync.mjs <คำสั่ง>
```

| คำสั่ง | ทำอะไร |
|---|---|
| `status` | ดูว่าตั้งค่าแล้วหรือยัง ต่อ panya ได้ไหม แต่ละ brain มีกี่ไฟล์ |
| `push memory <โฟลเดอร์ memory>` | ส่งความจำของโปรเจกต์นั้น (`--all` = ทุกโปรเจกต์ใน `~/.claude/projects`) |
| `push skills [ชื่อ ...]` | ส่งสกิล ไม่ระบุชื่อ = ทุกสกิลใน `~/.claude/skills` |
| `pull memory <โฟลเดอร์ memory>` | ดึงความจำกลับมาเป็นไฟล์ |
| `pull skills [ชื่อ ...]` | ดึงสกิลกลับมาเป็นไฟล์ |
| `list memory` / `list skills` | ดูว่าใน panya มีชุดไหนบ้าง |
| `search "<คำถาม>"` | ค้นใน panya (`--memory` หรือ `--skills` เพื่อค้นฝั่งเดียว) |

**ทุกคำสั่ง push และ pull ถ้าไม่ใส่ `--go` จะแสดงแผนเฉย ๆ ไม่ส่ง ไม่เขียนไฟล์**

## ขั้นตอนที่ต้องทำทุกครั้ง

1. รัน `status` ก่อน ถ้าขึ้นว่ายังไม่ได้ตั้งค่า ให้บอกผู้ใช้สร้างไฟล์ `~/.claude/panya.env` (ดูหัวข้อตั้งค่า) **อย่าขอให้ผู้ใช้พิมพ์ key ลงแชต และอย่าเดา URL เอง**
2. รันคำสั่งแบบไม่มี `--go` แล้วอ่านแผน: จำนวนไฟล์ รายการที่ถูกปิดข้อมูลลับ รายการที่ถูกข้าม
3. ใส่ `--go` เมื่อผู้ใช้สั่งส่งหรือสั่งดึงในข้อความล่าสุดแล้วเท่านั้น
   - push คือการส่งข้อมูลออกนอกเครื่อง ถ้าปลายทางเป็นเซิร์ฟเวอร์ที่คนอื่นเข้าได้ ให้ย้ำกับผู้ใช้ก่อน
   - pull สกิลคือการเอาสคริปต์จากเซิร์ฟเวอร์มาวางในเครื่อง ใครเขียนลง brain นั้นได้ก็ใส่โค้ดเข้ามาได้ ให้ดูรายชื่อไฟล์ใหม่ในแผนก่อนเสมอ
4. รายงานตามบรรทัดสรุปท้ายผลลัพธ์ สคริปต์ตรวจกลับเองทุกครั้ง: หลัง push จะส่งออกจาก panya มาประกอบใหม่แล้วเทียบ sha256 หลัง pull จะอ่านไฟล์ที่เขียนมาเทียบ sha256 ถ้าขึ้น ‼ หรือ exit code ไม่ใช่ 0 ให้บอกว่าไม่ผ่าน อย่าสรุปว่าเสร็จ

โฟลเดอร์ memory ของเซสชันปัจจุบันดูได้จาก system prompt (หัวข้อ Memory) ส่งพาธนั้นให้คำสั่ง

## ตั้งค่า

ไฟล์ `~/.claude/panya.env` (ตัวแปรแวดล้อมชื่อเดียวกันชนะค่าในไฟล์):

```
PANYA_URL=$PANYA_URL
PANYA_KEY=pnu_...   # สร้างที่หน้า บัญชีและ API (/account) ของเว็บ panya ให้ผู้ใช้ใส่เอง
# ไม่ใส่สองบรรทัดล่างก็ได้ ค่าตั้งต้นคือ claude-memory และ claude-skills
PANYA_BRAIN_MEMORY=claude-memory
PANYA_BRAIN_SKILLS=claude-skills
```

ปลายทางมีสองแบบ สคริปต์ดูจาก URL เอง:

- **panya บนคลาวด์ (ค่าหลัก)** `PANYA_URL=$PANYA_URL` ใช้ API key ของผู้ใช้ (`pnu_...`) จากหน้าบัญชี หรือ key เครื่องที่ผู้ดูแลออกให้ ทำได้ครบทุกคำสั่ง เขียนได้เฉพาะสมองที่ key นั้นเขียนได้ (key อ่านอย่างเดียวหรือจำกัดสมองจะ push ไม่ได้)
- **panya ตรงในเครื่อง/LAN** `PANYA_URL=http://host:6800` ใช้ key จาก `PANYA_API_KEYS` ของเซิร์ฟเวอร์นั้น
- **บริการฝากสมอง myWeekend** `PANYA_URL=https://myweekend.fun/api/brain/v1` ใช้โทเคน `mw_br_...` แบบเขียนได้จากหน้า `/account/brain`
  - ไม่มีคำสั่งลบ `--prune` จึงใช้ไม่ได้ และชิ้นเก่าของไฟล์ที่สั้นลงจะค้างอยู่ในสมอง (ดึงกลับยังได้ไฟล์ที่ถูก เพราะใบกำกับบอกจำนวนชิ้น)
  - ทุกชิ้นนับเป็นหนึ่งความจำในเพดานของแพ็กเกจ และ `search` หนึ่งครั้งตัดโควตาหนึ่งคำถาม ดูจำนวนในแผนก่อนส่ง
  - ไม่ตั้งชื่อ brain = ใช้สมองตั้งต้นของบัญชี ความจำกับสกิลจะอยู่ในสมองเดียวกัน

## สิ่งที่ต้องรู้

- **ข้อมูลลับถูกปิดก่อนส่งเสมอ** (โทเคน key สายอักขระฐานสิบหกยาว 32 ตัวขึ้นไป) แผนจะบอกว่าไฟล์ไหนโดนกี่จุด ไฟล์นั้นเมื่อดึงกลับจะมีคำว่า `[redacted]` แทนค่าจริง และ **จะไม่ถูกเขียนทับไฟล์ที่มีอยู่ในเครื่องแม้ใส่ `--force`** ต้องการส่งค่าจริงใช้ `--no-redact` ซึ่งต้องให้ผู้ใช้สั่งเองตรง ๆ
- **panya ไม่เก็บความลับ**: เซิร์ฟเวอร์ปฏิเสธชิ้นที่ดูเหมือนรหัสผ่าน key token หรือ URL ที่มีรหัส (แม้หลุดจากการปิดฝั่งเครื่อง) สคริปต์ข้ามเฉพาะชิ้นนั้นและขึ้น ‼ พร้อมชื่อไฟล์ ไฟล์นั้นจะตรวจ sha256 ไม่ผ่านและดึงกลับไม่ได้จนกว่าจะแก้ต้นทางให้เป็นค่าสมมุติ (`<your-key>`) แล้ว push ใหม่ `--no-redact` ไม่ช่วยให้ผ่าน
- **ไฟล์ที่ไม่ถูกส่ง**: ไฟล์ไบนารี (ฟอนต์ รูป PDF) ไฟล์ใหญ่กว่า 256 KB ไฟล์ `.bak` `.pyc` โฟลเดอร์ `node_modules` `.git` `__pycache__` `.venv` และสกิลในโฟลเดอร์ `synced` สกิลที่พึ่งไฟล์พวกนี้ต้องย้ายไฟล์เองอีกทาง แผนจะแสดงรายการที่ข้ามทุกครั้ง
- **pull ไม่ทับไฟล์ที่เนื้อหาต่างกัน** ถ้าไม่ใส่ `--force` ไฟล์ที่ตรงกันอยู่แล้วถูกข้าม ไฟล์ที่ประกอบแล้ว sha256 ไม่ตรงใบกำกับไม่ถูกเขียน
- **push ส่งเฉพาะไฟล์ที่เปลี่ยน** เทียบจาก sha256 ของไฟล์ในเครื่องกับใบกำกับใน panya ไฟล์ที่ลบจากเครื่องแล้วยังอยู่ใน panya จนกว่าจะใส่ `--prune`
- **push ครั้งแรกช้า** เพราะ panya ต้องทำ embedding ทุกชิ้น วัดบนโน้ตบุ๊กเครื่องนี้ 12 ต.ค. 2026: ความจำ 320 ไฟล์ (2,552 ชิ้น) ใช้ 3 นาที 32 วินาที รันเบื้องหลังได้ รอบถัดไปส่งเฉพาะไฟล์ที่เปลี่ยน
- **ย้ายความจำข้ามเครื่อง**: ชื่อโปรเจกต์คือชื่อโฟลเดอร์ที่ครอบ `memory` อยู่ (เช่น `d--Project-docksync`) ถ้าเครื่องปลายทางใช้พาธต่างกัน ให้ใส่ `--project <ชื่อเดิม>` ตอน pull
- **คำถามภาษาไทยใน Git Bash**: อักษรไทยใน argument กลายเป็น `?????` ให้เขียนคำถามลงไฟล์ UTF-8 แล้วใช้ `search --q-file <ไฟล์>` (PowerShell ส่งไทยตรง ๆ ได้)
- ของที่ส่งด้วย `scripts/push-claude-memory.ts` ในโปรเจกต์ panya (รุ่นก่อน) ค้นได้แต่ดึงกลับเป็นไฟล์ไม่ได้ เพราะไม่มีใบกำกับ ส่งใหม่ด้วยสกิลนี้จะแทนของเดิมของไฟล์เดียวกันให้เอง (เฉพาะ panya ตรง)

## รูปแบบที่เก็บใน panya

หนึ่งไฟล์กลายเป็นหลายความจำ ใช้ `source` และ `subject` เดียวกันทั้งไฟล์:

| ชนิด | source | subject |
|---|---|---|
| ความจำ | `<โปรเจกต์>/<ไฟล์>` | `claude-memory/<โปรเจกต์>/<ไฟล์>` |
| สกิล | `claude-skill/user/<สกิล>/<พาธ>` | เหมือน source |

- `attribute: description` คำอธิบายจาก frontmatter (ช่วยตอนค้น ไม่ใช้ตอนประกอบไฟล์)
- `attribute: p1..pn` เนื้อไฟล์ ตัดตรงขึ้นบรรทัดใหม่ ชิ้นละไม่เกิน 900 ตัวอักษร ช่องว่างที่อยู่ก่อนชิ้นเก็บใน `ref` เป็นรหัส `sep:nnss` (n ขึ้นบรรทัด r คือ CR s เว้นวรรค t แท็บ) เพราะ panya ตัดช่องว่างหัวท้ายของทุกข้อความ
- `attribute: file` ใบกำกับเป็น JSON: จำนวนชิ้น sha256 ของเนื้อที่เก็บ sha256 ของไฟล์ต้นทาง จำนวนจุดที่ถูกปิด และเวลาที่ส่ง

## เทสต์

```
cd ~/.claude/skills/panya-sync/scripts && node --test panya-sync.test.mjs
```

เทสต์ใช้เซิร์ฟเวอร์จำลองที่ทำตัวเหมือน panya (ตัดช่องว่าง ทับด้วย subject+attribute ลบตาม source) แก้สคริปต์แล้วต้องรันให้ผ่านครบก่อนใช้กับข้อมูลจริง
