# craft-boq — ถอดแบบ BOQ งานเฟอร์นิเจอร์ / งานไม้

สกิลนี้ทำงานแบบ **ช่างประมาณราคาที่มีประสบการณ์ 20 ปี** ไม่ใช่เครื่องคิดเลข
หลักการเดียวที่ห้ามละเมิด: **ถอดจากแบบ ไม่ถอดจากใบขอราคา** และ **ห้ามเดา — สิ่งที่แบบไม่ระบุให้เข้า RFI**

---

## 0. กฎเหล็ก 5 ข้อ

1. **แบบ (PDF) = แหล่งมิติ / Excel = ปลายทางและขอบเขต** ใบขอราคามักเขียนแค่ "ตามแบบแนบ" ใช้คิดของไม่ได้
2. **อ่านเฉพาะ FRONT + SECTION ที่มีตัวเลขกำกับ** ห้ามสเกลจากรูป ห้ามวัดพิกเซล
3. **ตรวจยอด 2 ทางเสมอ** — ผลรวมระยะย่อยต้องเท่ากับ overall ถ้าไม่เท่าแปลว่าอ่านผิดหรือเป็นคนละ chain
4. **สิ่งที่แบบไม่ระบุ / แบบกับ BOQ ขัดกัน → RFI ไม่เดา ไม่เลือกข้างเงียบๆ**
5. **ราคาต้องย้อนสอบได้** — ทุกตัวเลขต้องโยงถึงแผ่นที่ถอดได้ และอัตราต้องอยู่ในชีตเดียว (`RATE`) ที่แก้ที่เดียวแล้วอัปเดตทั้งไฟล์

---

## 1. ถามผู้ใช้ก่อนเริ่ม (ถ้ายังไม่ชัด)

ถามให้ครบ 3 ข้อนี้ก่อนลงมือ — ตอบต่างกันคือทำคนละงาน

| คำถาม | ทำไมต้องถาม |
|---|---|
| **สเปกขัดกันให้ยึดอะไร** (BOQ / แบบ / ถอดทั้งคู่เทียบ) | ต่างกันได้ 20–35% ของราคา |
| **หน่วยเสนอราคา** (เหมาชุด / ต่อ ตร.ม. / ต่อเมตร) | กระทบรูปแบบไฟล์ส่งมอบ |
| **ขอบเขต** (เฉพาะที่ BOQ ขอ / รวมรายการอื่นในผัง / รวมงานระบบ-สุขภัณฑ์ไหม) | กันงานบานปลาย |

ถ้าผู้ใช้ตอบ "ยึด BOQ" **แต่แบบเขียนต่าง** → ยังต้องถอด 2 เคสเทียบ แล้วเสนอราคาด้วยเคส BOQ

---

## 2. เช็คไฟล์ (Step 1)

```bash
python "<SKILL_DIR>/scripts/pdf_probe.py" "<แบบ.pdf>" --outdir "<scratch>/pages"
```

สคริปต์จะรายงาน:
- จำนวนหน้า / หน้าไหนเป็น vector CAD (ถอดได้) หน้าไหนเป็นรูป 3D หรือสแกน
- ป้ายชื่อวิว (`FRONT`, `SECTION-x`, `ELEVATION-x`, `PLAN`) ต่อหน้า → ใช้จับคู่หน้ากับรหัสรายการ
- รหัสรายการที่พบ (`B1`, `F2`, `D1` …) → ตรวจว่าครบตามที่ BOQ ขอไหม
- เรนเดอร์ทุกหน้าเป็น PNG 200 dpi ให้อ่านต่อ

ฝั่ง Excel ใช้ `openpyxl` อ่านทั้งชีต แล้วเช็ค 4 อย่างเสมอ:
- คอลัมน์ "ขนาด" มีค่าจริงหรือเขียน "ตามแบบแนบ"
- **สูตร SUM ครอบคลุมทุกแถวไหม** (เจอบ่อยมากว่าช่วงสูตรตกหล่นแถวท้าย)
- สเปกที่ผู้ว่าจ้างสั่งทับแบบ (ยี่ห้อฮาร์ดแวร์ รหัสลามิเนต หมายเหตุ `***`)
- หมายเหตุขอบเขต เช่น "เสนอราคาสินค้าพร้อมติดตั้ง"

> ⚠️ ข้อความไทยใน PDF งานเขียนแบบมัก extract ไม่ออก (ฟอนต์ไม่ฝัง ToUnicode) **ตัวเลขออกครบ** — ให้เรนเดอร์เป็นภาพแล้วอ่านด้วยตา อย่าเชื่อ `pdftotext` อย่างเดียว

## 3. อ่านมิติ (Step 2)

อ่านทีละรายการ บันทึกลงตารางกลางก่อน อย่ารีบแตกแผ่น:

`Code | ชื่อ | W | H | D | จำนวนช่อง | บานเปิด | ลิ้นชัก | ชั้นปรับระดับ | ชั้นตาย | หมายเหตุพิเศษ`

**วิธีอ่านสัญลักษณ์ที่ต้องรู้**

| สิ่งที่เห็นในแบบ | ความหมาย |
|---|---|
| เส้นประรูป **ข้าวหลามตัด (diamond)** | บานเปิด **คู่** — ยอดข้าวหลามตัดคือแนวบานชนกัน |
| เส้นประรูป **สามเหลี่ยม** ยอดชี้ข้างเดียว | บานเปิด **เดี่ยว** ยอดอยู่ฝั่งมือจับ |
| เส้นประ**แนวนอน**ในรูปด้าน | ชั้นวางที่มองทะลุบาน |
| ลูกศร `WOODLINE` | ทิศลายไม้ — ต้องล็อกลายต่อเนื่อง เผื่อเศษเพิ่ม |
| `SP = n เล่ม` / `GL = n เล่ม` | ความจุที่ผู้ออกแบบคำนวณไว้ ใช้ cross-check จำนวนช่อง |

**สูตรตรวจยอดที่ใช้ได้เสมอ**
```
W_รวม = แผงข้าง + Σ(บาน) + แผงข้าง        เช่น 25 + 422×18 + 25 = 7646 ≈ 7650 ✓
H_รวม = บังตาบน + บานบน + คิ้วมือจับ + บานล่าง + ตีนตู้
D_รวม = ผิวหน้า + ช่องใน + ผิวหลัง        (ยึดรูปตัด ไม่ยึดผัง — ผังมักวัดถึงผนัง)
```
ถ้าจำนวนช่อง × ระยะไม่ลงตัวกับ overall ให้กลับไปซูมอ่านใหม่ ห้ามปัดให้ลงตัวเอง

ซูมด้วย:
```bash
python "<SKILL_DIR>/scripts/pdf_probe.py" "<แบบ.pdf>" --crop 3 0.28 0.36 0.66 0.90 --dpi 450 --name B1_front_L
```

## 4. ถอดรายแผ่น (Step 3 — งานหลัก)

ใช้ `scripts/takeoff_lib.py` เขียนโมเดลเป็นโค้ด ไม่กรอกมือ (แก้ทีเดียวคำนวณใหม่ทั้งชุด)

```python
import sys; sys.path.insert(0, r"<SKILL_DIR>/scripts")
from takeoff_lib import Takeoff

t = Takeoff()                       # ค่าเริ่มต้น: แผ่น 1220×2440, HMR18, ขอบ PVC

# โครงตู้มาตรฐาน 1 บรรทัดจบ (แผงตั้ง+กั้น / บน-ล่าง / หลัง / ชั้นปรับระดับ)
t.carcass("B3", W=2000, H=1050, D=450, ncomp=5, comp_w=370,
          ext_face="GSB107", int_face="PW201P", n_shelf=2)
t.P("B3","หน้าบาน","HMR18","GWE5101","PW201P", 390,1090, 18, qty=5, edge=2*(390+1090))
t.P("B3","ท็อปบน","HMR18","GWE5101","PW201P", 2000,450, 18, qty=1, edge=2*(2000+450))
t.plinth("B3", W=2000, D=450)
t.hw("B3","บานพับ No Soft Close","ตัว", 5*3)

t.build(out="<โฟลเดอร์ส่งมอบ>/01_Cutting_List_and_Pricing.xlsx",
        items=ITEMS, slots={"B7":852})
```

**กฎการแตกแผ่น** อ่าน `references/panel-model.md` — ครอบคลุม: จำนวนแผงตั้ง = ช่อง+1, ชั้นร่นหน้า 30 มม.,
บานคาบแผงกั้น, ตู้ชนหลัง (2 หน้า) นับ 2 โครง, ตู้แยก BODY บน-ล่างนับ 2 ชุดบน-ล่าง

**ตรวจก่อนไปต่อ:** ผลรวมมิติแผ่นต้องกลับมาเท่า overall ของ Step 2 — ถ้าไม่ตรงคือตกหล่นหรือนับซ้ำ

## 5. ม้วนเป็นปริมาณสั่งซื้อ + ราคา (Step 4–5)

`takeoff_lib` ทำให้อัตโนมัติ:
- พื้นที่ ตร.ม. แยกตามวัสดุซับสเตรตและรหัสลามิเนต (นับผิว 2 หน้าแยกกัน)
- **เผื่อเศษ** ซับสเตรต 10% · ลามิเนตทั่วไป 10% · **ลามิเนตลายไม้/ลายหิน 15%** (ต้องล็อกทิศลาย) · ขอบ PVC 5%
- แปลงเป็นจำนวนแผ่น 1220×2440 (ปัดขึ้น)
- ประกอบราคา: `วัสดุ + ลามิเนต + ขอบ + งานพิเศษ + ฮาร์ดแวร์ + ค่าแรง → +ขนส่ง/ติดตั้ง → +OH → +กำไร`

**ค่าแรงต้องแยกงานที่แรงสูงผิดปกติออกมาเป็นบรรทัดของตัวเอง**
เช่น ตู้ช่องเก็บแผ่นตัวอย่าง 852 ช่อง ถ้าคิดรวมเป็น บาท/ตร.ม. จะต่ำกว่าความจริงมาก → ตั้ง `LAB_SLOT` บาท/ช่อง แยก

อัตราตั้งต้นและช่วงราคาตลาด ดู `references/rates.md`
**ต้องเขียนเตือนเสมอว่าอัตราเป็นค่าประมาณ ต้องให้ฝ่ายจัดซื้อ/โรงงานยืนยัน**

## 7. RFI Checklist — ต้องไล่ทุกข้อทุกครั้ง

ดูรายละเอียดและตัวอย่างถ้อยคำใน `references/rfi-checklist.md`

- [ ] สเปกโครงสร้างใน BOQ กับหมายเหตุในแบบ **ตรงกันไหม**
- [ ] สูตรรวมใน BOQ ครอบคลุมทุกแถวไหม
- [ ] ช่อง "ขนาด" ว่างหรือเขียน "ตามแบบแนบ" ไหม
- [ ] ความหนา/วัสดุ **แผงหลัง** ระบุไหม
- [ ] การแบ่งช่องภายในระบุไหม (แบบให้แต่ระยะบาน)
- [ ] ยี่ห้อ/รุ่น **หินท็อป / ฮาร์ดแวร์ / ลามิเนต** ใน BOQ กับแบบตรงกันไหม
- [ ] ความหนาชิ้นส่วนย่อยในคำบรรยาย กับ **แบบขยาย** ตรงกันไหม
- [ ] ผิวสำเร็จ (พ่นสี vs ปิดลามิเนต) ระบุขัดกันไหม
- [ ] มิติในผัง กับ **รูปตัด** ตรงกันไหม (ยึดรูปตัด)
- [ ] งานระบบ/สุขภัณฑ์/เครื่องใช้ไฟฟ้า อยู่ในขอบเขตไหม
- [ ] รายการที่โผล่ในผังแต่ไม่มีในใบขอราคา — แจ้งว่านอกขอบเขต
