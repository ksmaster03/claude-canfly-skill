## ขั้นตอน

1. **ดึงหน้าเว็บ** `python $T/fetch_page.py <URL> <PROJ>`
   → `text.txt` (ข้อความทั้งหน้า รวมตารางสเปกและ FAQ) · `src/NN.mp4` (วิดีโอทุกตัว ความละเอียดสูงสุด) · `src_info.txt` (ขนาด/ความยาว/หัวข้อที่คลิปนั้นอยู่)
   - ดาวน์โหลดเฉพาะ https จากโฮสต์ของหน้าเว็บเอง (รวมซับโดเมน) กับ `cdn.shopify.com` · ถ้าขึ้น "ข้ามโฮสต์ที่ไม่อยู่ในรายการอนุญาต" และเป็น CDN ของแบรนด์จริง ให้เติม `--allow-host <โฮสต์>` (อย่าเติมโดยไม่ดูว่าเป็นของใคร: URL พวกนี้มาจาก HTML ภายนอกแล้วถูกส่งเข้า ffmpeg) · ไฟล์ที่ไม่ใช่ MP4/WebM จริงจะถูกทิ้ง
   - อ่าน `text.txt` ให้ครบทุกบรรทัด สเปกจริงอยู่ท้ายหน้า (ตาราง Specs, What's in the box, FAQ)
   - เสริมด้วย WebSearch รีวิวจากสื่อ เพื่อหา **ราคา** และ **ข้อเสีย** ที่หน้าเว็บผู้ผลิตไม่บอก
2. **ดูฟุตเทจ** `python $T/sheets.py <PROJ>` แล้ว Read `sheets/grp*.jpg` (คลิปสั้น) และ `sheets/long_*.jpg` (คลิปยาว 1 เฟรม/วิ มีเลขวินาที)
   - เว็บมักมีคู่ desktop (แนวนอน 1080p) กับ mobile (แนวตั้ง/4:3 720p) — ใช้แนวนอน
   - คลิปยาว ๆ ที่เป็นหนังเปิดตัว คือแหล่งช็อตสินค้าระยะใกล้ที่ดีที่สุด จด in-point จาก sheet
3. **เขียนบท** `<PROJ>/script.json` + `<PROJ>/config.json` (schema ด้านล่าง) — **แสดงบทให้ผู้ใช้ดูก่อนเรนเดอร์** ถ้าผู้ใช้ไม่ได้บอกให้ทำรวดเดียว
4. **เสียงพากย์** `python $T/make_vo.py <PROJ>` (สร้างใหม่เฉพาะท่อนที่ข้อความเปลี่ยน)
5. **ประกอบ** `python $T/build.py <PROJ>` (ตัดใหม่เฉพาะช็อตที่เปลี่ยน; `--fresh` = ตัดใหม่หมด) → `<PROJ>/<name>.mp4`
6. **ตรวจ** (ห้ามข้าม) — ดูหัวข้อ "ตรวจก่อนส่ง"

## โครงบทที่ใช้ได้ผล (รีวิวละเอียด ~5 นาที, 18–22 ช่วง)

hook (สิ่งที่ทำให้สินค้านี้ไม่เหมือนใคร) → คืออะไร/ของใคร → ตัวเครื่อง+น้ำหนัก → จุดขายหลักทีละเรื่อง (1 ฟีเจอร์ = 1 ช่วง)
→ ตัวควบคุม/แอป → โหมดใช้งาน → กล้อง/คุณภาพ → สมรรถนะ (ตัวเลข) → ราคา + ของในกล่อง + ซื้อในไทยได้ไหม
→ **ข้อสังเกตก่อนซื้อ 4–5 ข้อ** → สรุปว่าเหมาะกับใคร/ไม่เหมาะกับใคร → CTA เอ่ยชื่อช่อง

- ข้อเสียต้องมีเสมอ ไม่งั้นเป็นโฆษณาไม่ใช่รีวิว ดึงจาก FAQ ของผู้ผลิตเอง (เช่น "ไม่มีระบบหลบสิ่งกีดขวาง", "แบตกันน้ำเฉพาะตอนเสียบในเครื่อง") + รีวิวสื่อ
- ข้ออ้างที่ผู้ผลิตใส่ดอกจัน (ผลแล็บ, เวลาบินในสภาพทดสอบ) ให้พูดว่า "ผลทดสอบในแล็บ" / "ผู้ผลิตบอกว่า"
- **บริบทไทย**: กฎหมายไทยอาจต่างจากที่หน้าเว็บอ้าง (เช่น โดรนติดกล้องทุกขนาดต้องลงทะเบียน กสทช. + กพท. แม้หน้าเว็บบอกว่าต่ำกว่า 250 กรัมไม่ต้อง) · หน้าเว็บบอก "not offer services in your area" = ยังไม่ส่งตรงมาไทย
- ราคาให้บอกเป็นสกุลเงินต้นทาง อย่าแปลงเป็นบาทเองถ้าไม่ได้เช็กเรตวันนั้น
- ภาษา: ไทยธรรมดา อ่านลื่น ห้ามขีดยาว ห้ามภาษาแปล
- **ประโยค hook**: หยิบแม่แบบจากคลัง `~/.claude/skills/vidcraft/references/hooks-50.md` รีวิวเหมาะกับกลุ่มทดลองแทนคนดูในรูปคำถาม (6, 14, 25) กลุ่มเปรียบเทียบ (47) และข้อ 11, 37 · สกิลนี้ประกอบจากข้อมูลและฟุตเทจของผู้ผลิต **ห้ามใช้ข้อที่อ้างว่า "ผมลองทดสอบ" หรือ "ผมใช้แล้ว"** (2, 16, 30, 41) เว้นแต่ผู้ใช้ทดสอบสินค้าจริง
- **บทเรียนรวมก่อนเขียนบทและผสมเสียง**: `~/.claude/skills/vidcraft/references/reel-lessons.md` (กะความยาว 10 ตัวอักษรต่อวินาทีสำหรับ Lumina · เพลงเบากว่าเสียงพากย์ 10 ถึง 12 dB · ตัดตรงตรงช่องหายใจ · โครงสองความเร็ว)

## script.json
```json
[{"id":"s03","sfx":"whoosh","kicker":"ตัวเครื่อง และน้ำหนัก",
  "th":"น้ำหนักสองร้อยสี่สิบเก้ากรัม ... ไอพี หกเจ็ด ... อาร์ทีเค",
  "sub":"น้ำหนัก 249 กรัม|... IP67 ...|... RTK",
  "chip":"249 g  |  Class C0 (EU)",
  "shots":[["02",20.0],["00",14.0],["15",3.0]],
  "tail":0}]
```
- `th` = บทพูดที่ส่ง TTS ตรง ๆ → **เขียนชื่อสินค้า ตัวเลข และศัพท์อังกฤษเป็นคำอ่านไทย** (Tinglish dict ไม่รู้จักชื่อสินค้าใหม่ และ edge-tts อ่าน "IP67" / "1/1.28" เพี้ยน)
- `sub` = ซับบนจอ คั่นท่อนด้วย `|` ท่อนละไม่เกิน ~45 ตัวอักษร ใช้ตัวเลข/ชื่อภาษาอังกฤษสวย ๆ ได้ (เวลาแต่ละท่อนแบ่งตามจำนวนตัวอักษรอัตโนมัติ)
- `kicker` = ป้ายหัวข้อมุมซ้ายบนพร้อมเลขลำดับ (เว้นว่างในช่วง hook/CTA) · `chip` = ป้ายสเปกมุมขวาบน (ออปชัน)
- `shots` = `[key, วินาทีเริ่ม]` เวลาของช่วงถูกแบ่งเท่า ๆ กันให้ทุกช็อต (ช็อตที่ต้นฉบับสั้นไม่พอจะเกลี่ยให้ช็อตอื่น) → 1 ช็อตควรได้ 2–4 วิ = ใส่ช็อตราว `ความยาวเสียง / 2.5`
- `sfx:"whoosh"` = เสียงวูบตอนเข้าช่วง · `tail` = ยืดช่วงสุดท้ายไว้โชว์การ์ดปิด (ใช้ 4)

## config.json
```json
{"name":"Product_Review_TH", "title":["HOVERAir","AQUA"], "subtitle":"รีวิวละเอียด ...",
 "credit":"โกสินทร์ต้องบินได้",
 "end_note":"ภาพและวิดีโอประกอบ: <แบรนด์> (<โดเมน>)  ·  เพลง: <ศิลปิน>",
 "accent":[255,107,20], "voice":"th-TH-NiwatNeural", "rate":"+6%",
 "bgm":["$MEDIA/bgm/....mp3", "..."], "bgm_skip":16, "bgm_vol":0.55, "crf":20,
 "crop":{"02":[{"from":88,"to":124,"z":1.34,"anchor":"left"},{"z":1.12}]}}
```
- **credit**: ผู้ใช้ต้องการเครดิต "โกสินทร์ต้องบินได้" ทุกคลิป → build ใส่ 3 จุด: ใต้ไตเติลเปิด, ลายน้ำมุมขวาบนตลอดคลิป, การ์ดปิด และให้เอ่ยชื่อช่องในบท CTA ด้วย
- **end_note**: ให้เครดิตแหล่งฟุตเทจ (เว็บผู้ผลิต) และเพลงทุกครั้ง
- **accent**: สีแบรนด์สินค้า (RGB) ใช้กับคำที่สองของ title และเลขหัวข้อ
- **bgm**: เลือกจาก `$MEDIA/bgm` (เคลียร์สิทธิ์แล้ว ดู `$MEDIA/README.md` มี BPM/intro) **ห้ามใช้ `_unknown-licence/`** · เลือกเพลงบรรเลงไม่มีเสียงร้อง (ชนกับเสียงพากย์) · ต่อหลายเพลงได้ (crossfade 3 วิ) ให้ยาวรวมเกินความยาวคลิป · `bgm_skip` = ข้ามอินโทรเงียบของเพลงแรก (ดูค่า intro ใน README) ไม่งั้นไตเติลเปิดเงียบ
- **crop**: คลิปผู้ผลิตบางตัวฝังซับ/ป้ายอังกฤษไว้ด้านล่าง → ซูมครอปจากขอบบน `z` เท่า · `anchor:left` เมื่อมุมซ้ายบนมีโลโก้ที่ไม่อยากให้ถูกตัดครึ่ง · กฎแรกที่ช่วงเวลา (`from`/`to` = วินาทีเริ่มของช็อต) ตรงชนะ

## โหมดไม่มีเสียงพากย์ (เพลงล้วน + ตัวหนังสือ) — `build_music.py`
ใช้เมื่อผู้ใช้ขอ "ไม่ต้องมีเสียงพากย์" / "เอาแค่เพลง" / อยากได้คลิปมันขึ้น ความยาวคลิป = ความยาวเพลง (~3 นาที)
1. **เพลงจาก Suno** ด้วยสกิล [[sunobridge]]: `cd $PROJECTS/suno-bridge && node create.mjs --lyrics <ไฟล์ว่าง> --instrumental --styles "..." --title "..." [--dry]`
   สไตล์ที่ได้ผล (AQUA): `high-energy instrumental, action sports trailer, electronic rock, 132 bpm, driving punchy drums, heavy bass drops, distorted electric guitar riffs, bright synth leads, risers and impacts, adrenaline, summer ocean, epic build-ups, no vocals`
   ซ้อม `--dry` แล้ว Read `debug/filled.png` (ปุ่ม Create ต้องเป็นสีส้ม) ก่อนสั่งจริง เพราะสั่งจริงกินเครดิต
2. **วัดเพลง** `python ~/.claude/skills/vdomindset/references/downbeat.py <take>.wav` → bar + phase (เลือกเทคที่ score สูงกว่า)
   แล้วดูกราฟความดังราย 2 บาร์ (ebur128 ค่า M) หา **ช่วงพัก** (ดังลดลง 2 dB ขึ้นไป) — Suno บีบไดนามิกจนแบน จุดพักจึงเห็นแค่ราว -18 เทียบ -16
3. `<PROJ>/music.json` = `{"music": "...wav", "bar": 1.7647, "phase": 0.12, "name": "..._Music", "end_note": "... · เพลง: สร้างด้วย Suno", "gain_db": 2}`
4. `<PROJ>/music_script.json` แต่ละช่วงกำหนดความยาวเป็น **บาร์** ผ่าน shots `[key, start, bars?]` (ไม่ใส่ = 1 บาร์ ≈ 1.8 วิ ตัดถี่ = มัน)
   - `lines`: ข้อความใหญ่มุมซ้ายล่าง แบ่งบาร์ของช่วงเท่า ๆ กัน → 1 บรรทัดควรได้ ≥ 2 บาร์ (~3.5 วิ) ให้อ่านทัน ข้อความสั้น ไม่เกิน ~35 ตัวอักษร
   - วางช่วงให้ **รอยต่อตรงช่วงพักของเพลง**: ช่วงพักใส่ฉากช้า/ลอยน้ำ ช่วงที่กลับมาแรงใส่ `"flash": true` (แฟลชขาว)
   - ช่วงสุดท้าย `"rest": true` = การ์ดปิดเครดิตยืดถึงจบเพลง
   - ช่วงแรกไม่มี lines (ไตเติลการ์ด) · ช่วง hook ใส่ `"hook": true` = ตัวใหญ่ 128 กลางจอ ขึ้นทีละตัวจากเบลอ + แถบสีแบรนด์ขีดตามใต้ข้อความ
   - ข้อความทุกบรรทัดขึ้นทีละตัว (`reveal()` แยกตามกลุ่มอักษรไทย ฐาน+สระบน/ล่าง/วรรณยุกต์/สระอำ ไม่งั้นสระลอย) ขนาด 104 ตัดบรรทัดอัตโนมัติ
   - **transition**: ทุกรอยต่อเป็น xfade ที่กึ่งกลางตรงบีต (ช็อตยาวเกินขอบบาร์ข้างละครึ่ง) ภายในหัวข้อ = `fade` 8 เฟรม ข้ามหัวข้อ = 16 เฟรมวนชุด zoomin/circleopen/slideleft/... ช่วง flash = fadewhite · บังคับต่อช่วงด้วย `"tr": "<ชื่อ xfade>"` · ปรับใน music.json `tr_in_frames` / `tr_sec_frames` / `sec_transitions`
   - xfade ต่อทีละก้อน 12 ช็อตแล้วต่อก้อนอีกชั้น (เปิด 100 อินพุตพร้อมกันกิน RAM) — offset คิดเป็นเฟรม จำนวนเฟรมสุดท้ายต้อง = ความยาวเพลง × 30
5. `python $T/build_music.py <PROJ>` · ตรวจ: จำนวนเฟรม = ความยาวเพลง × 30, I ≈ -14 LUFS (ปรับ `gain_db` ทีละ dB ไม่ใช้ loudnorm เพราะ Suno master มาแล้ว), peak ≤ -1 dB
   ตัวอย่างใช้งานจริง: `$WORK/tmp/aqua/skilltest/music_script.json` (22 ช่วง 102 บาร์ + การ์ดปิด)

## ตรวจก่อนส่ง
1. แคปเฟรมกลางช็อตของทุกคลิปที่มีตัวหนังสือฝัง (สำคัญสุดคือหนังเปิดตัว) แล้ว Read ดูว่ามีซับอังกฤษ/โลโก้ครึ่งตัว/กล่อง HUD โผล่ไหม — ซับฝังในหนังเปิดตัวอยู่ไม่เท่ากันทุกช่วง (ของ AQUA ช่วง 1:28–2:04 อยู่สูงกว่าช่วงอื่น ต้องซูม 1.34 แทน 1.12)
2. แคปเฟรมแบบ tile 3x3 ทั่วคลิป: ซับไทยไม่ลอย/ไม่ตกขอบ, ป้ายหัวข้อตรงเนื้อหา, ช็อตตรงเรื่องที่พูด (เช่น ช่วงสมรรถนะอย่ามีคนนั่งคุยโผล่มา)
3. `ffprobe -count_packets` จำนวนเฟรมวิดีโอต้อง ≈ TOTAL×30 (ถ้าน้อยกว่า ภาพจะตัดก่อนเสียงช่วงท้าย)
4. `ebur128=peak=true`: I ≈ -14 LUFS, Peak ≤ -0.5 dBFS · `volumedetect` ช่วงไตเติล 0–3 วิ ควร > -20 dB (ได้ยินเพลง)
5. ส่งไฟล์ให้ผู้ใช้ด้วย SendUserFile ถ้าขนาดไหว หรือบอกพาธ + คัดลอกไป `~/Videos/<slug>/`

## ช็อตที่ไม่ควรใช้ (เจอตอนตรวจ)
- ช็อตที่มีป้ายฝังมุมซ้ายล่าง ชนข้อความใหญ่ของโหมดเพลง (AQUA: `02@20` ป้าย "< 249")
- ช็อตที่มีป้ายอังกฤษฝังมุมซ้ายบน แล้วโดนครอปตรงกลางตัดครึ่ง (AQUA: `02@12` "Fully sealed waterproof body")
- คลิปเทียบสองฝั่งที่มีโลโก้/ป้ายมุมซ้ายบน จะชนป้ายหัวข้อของเรา · ป้ายฝังด้านล่างจะชนซับ/ข้อความใหญ่
- ช็อตคนนั่งคุยกันในช่วงที่พูดถึงสเปก (ดูให้ช็อตตรงเรื่อง)

## กับดักที่เจอมาแล้ว
- **WebFetch เห็นแค่เมนู** ของหน้า Shopify/JS — ต้องดึง HTML ดิบ (fetch_page.py) วิดีโออยู่ใน `<source data-src=...mp4>`
- **แท็ก ASS ใน Python f-string**: `\fad` `\an` `\1c` `\b` กลายเป็นอักขระควบคุม (form-feed, bell, \x01, backspace) **เงียบ ๆ** ซับยังเรนเดอร์แต่เอฟเฟกต์หาย → ใช้ `r"..."` ต่อสตริง build.py มี assert ดักไว้แล้ว
- **ภาพเลื่อนจากเสียง**: ตัดช็อตด้วย `-t` แล้ว concat ทำให้ขาดไป 20 เฟรมใน 5 นาที → build.py ใช้ `-frames:v` บนกริดเฟรมสะสม + `-stream_loop -1` ทุกช็อต
- **ฟิลเตอร์ `ass=` กับพาธ `C:\`** escape ยากมาก → คัดลอกฟอนต์ Prompt มาที่ `<PROJ>/fonts` แล้วใช้พาธ relative (build.py ทำให้)
- ฟอนต์ไทยบนจอใช้ **Prompt** (มีตัวไทย) + `shaping=complex` ห้าม Arial/Inter/Segoe
- edge-tts ส่งข้อความผ่านไฟล์ `-f` เสมอ (Git Bash กลืนอักษรไทยใน argument)
- `loudnorm` รอบเดียวพุ่ง peak ถึง 0 dBFS ได้ → มี `alimiter` ปิดท้ายแล้ว
- ไฟล์ CRF 18 ยาว 5 นาทีหนัก ~475 MB → ใช้ CRF 20 (~390 MB)

## สิทธิ์ของฟุตเทจ
คลิปเป็นของผู้ผลิต ใช้ได้ในฐานะรีวิว/วิจารณ์ ต้องใส่เครดิตแหล่งที่มา (end_note) และอย่าตัดต่อให้ดูเหมือนเป็นโฆษณาทางการของแบรนด์ (ไม่ใช้โลโก้แบรนด์เป็นชื่อช่อง ไม่อ้างว่าเป็นตัวแทน)
ถ้าผู้ใช้จะยิงแอดหรือขายของต่อ ให้เตือนว่าควรขออนุญาตแบรนด์ก่อน
