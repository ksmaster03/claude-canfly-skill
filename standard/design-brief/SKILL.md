# บรีฟงานออกแบบ (Design Brief)

## ใช้ตอนไหน
ก่อนเริ่มงานออกแบบ (โลโก้/แบรนด์/กราฟิก/UI) เพื่อตกลงขอบเขตและความคาดหวังให้ตรงกัน

## ถามผู้ใช้ก่อน
1. งานอะไร + เพื่อใคร (กลุ่มเป้าหมาย)
2. เป้าหมาย/ปัญหาที่งานนี้ต้องแก้
3. โทน/อารมณ์ที่ต้องการ + ตัวอย่างที่ชอบ
4. ข้อจำกัด (สี/ฟอนต์แบรนด์ / ขนาด / เดดไลน์ / งบ)

## ขั้นตอน
1. สรุปวัตถุประสงค์และกลุ่มเป้าหมายให้ชัด
2. แปลคำพูดอารมณ์ ("ดูพรีเมียม") เป็นทิศทางที่ทำได้จริง
3. กำหนด deliverables + จำนวนรอบแก้ + ไทม์ไลน์
4. ระบุเกณฑ์ว่า "งานสำเร็จ" หน้าตาเป็นยังไง

## เทมเพลตผลลัพธ์
```
โปรเจกต์: ..   ลูกค้า: ..
วัตถุประสงค์: ..   กลุ่มเป้าหมาย: ..
โทน/อารมณ์: .. (คีย์เวิร์ด 3-5 คำ)
สิ่งที่ต้องส่งมอบ (deliverables): ..
ข้อจำกัด: สี.. ฟอนต์.. ขนาด.. 
ไทม์ไลน์ + จำนวนรอบแก้: ..
เกณฑ์งานสำเร็จ: ..
```

## เคล็ดลับ
- ขอ "ตัวอย่างที่ชอบ + ที่ไม่ชอบ" จะจับทิศทางได้แม่นกว่าคำบรรยายลอยๆ
- ระบุจำนวนรอบแก้ในบรีฟ ป้องกันแก้ไม่จบ
